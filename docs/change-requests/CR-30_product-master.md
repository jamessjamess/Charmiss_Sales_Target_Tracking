## ส่วน 1: เปลี่ยนแปลงระดับ Module

### 1.1 Status: `New` → `NPD`

- เปลี่ยนชื่อ Status `New` เป็น **`NPD`** ทั้งระบบ (Badge, ตัวกรอง, KPI, Plan Summary, คู่มือ, Export) · นิยามเดิม (3 เดือนแรกนับจากเดือนเปิดตัว)
- ชุด Status: `Planned` · `NPD` · `Active` · `Clearance` · `Discontinued`

### 1.2 Product Code

- เปลี่ยนป้าย `TR Code` → **`Product Code`** ทุกที่ (ชื่อฟิลด์ในโค้ดคงเดิมได้)
- **ระบบสร้างให้เสมอ** ตอนสร้างสินค้า ผู้ใช้กรอกเองไม่ได้ และ **แก้ไม่ได้หลังสร้าง** (ฟอร์มแก้ไขแสดงเป็นข้อความพร้อมไอคอนกุญแจ Tooltip `Product Code สร้างโดยระบบ แก้ไขไม่ได้`)
- กฎสร้างรหัส: `{เลขนำหน้าของ Type}{ลำดับ}` เป็นเลข 5 หลัก ถัดจากรหัสที่มากที่สุดในกลุ่มเดียวกัน ขั้นละ 10 (ตามรูปแบบรหัสเดิม เช่น Cushion `12240` → `12250`)
  - เลขนำหน้ากำหนดที่ Type ในหน้าหมวดสินค้า (ส่วน 7) · ค่าตั้งต้นคำนวณจากรหัสสินค้าที่มีอยู่ใน Type นั้น (2 หลักแรกที่พบมากที่สุด)
  - Type ที่ยังไม่มีเลขนำหน้า → สร้างสินค้าใน Type นั้นไม่ได้ พร้อมข้อความ `กำหนดเลขนำหน้า Product Code ของ Type นี้ก่อน`
  - แสดงรหัสที่จะได้ก่อนกดบันทึก · เลขที่ใช้แล้วไม่นำกลับมาใช้แม้สินค้าถูกปิดใช้งาน · เก็บเลขล่าสุดของแต่ละกลุ่มใน `master.codeCounters`
- **ตัดรหัสชั่วคราวและปุ่ม `ผูกรหัสจริง`** · ข้อมูลตั้งต้น `NPD_2027Q2_01–03` แปลงเป็นรหัสที่ระบบสร้าง และย้ายการอ้างอิงทั้งหมด (Listing, ราคา, แผน NPD, แผน SKU) ด้วยฟังก์ชันย้ายรหัสเดิม
- **Product Code เป็นเลขเดียวกับ TRCLOUD** (Product Master เป็นต้นทาง) · เพิ่มฟิลด์ `ใน TRCLOUD` = `เปิดแล้ว` / `ยังไม่เปิด` ตั้งค่าจากผลของปุ่ม `เปรียบเทียบกับ ERP` (ค่าตั้งต้น: สินค้าจาก seed = เปิดแล้ว · สินค้าที่สร้างใหม่ = ยังไม่เปิด)
- ปุ่มเปรียบเทียบกับ ERP: กลุ่ม `มีใน TRCLOUD แต่ไม่มีใน Product Master` มีปุ่ม `นำเข้าด้วยรหัสเดิม` (ไม่สร้างรหัสใหม่)

### 1.3 ตัดฟิลด์

- ตัด `Internal Code` และ `Item Type` (คอลัมน์ ฟอร์ม ตัวกรอง Export และค่าตั้งต้น `ขายจริง` ของตัวกรอง) · ไม่แยก Tester / ของแถม
- SKU Planning เลิกกรอง `itemType = SALE` (ทุกสินค้าเป็นสินค้าขาย)

### 1.4 ความครบถ้วนของข้อมูล

- จำเป็น: Product Code · ชื่อ · Category · Sub Category · Type · Series · RSP · เดือนเปิดตัว
- ควรมี: **Barcode · รูปสินค้า** (ตัด Internal Code และ Sub Series ออกจากกฎ)
- NPD ที่ Sales สร้างยังยกเว้นกฎ "ขาดข้อมูลจำเป็นใช้วางแผนไม่ได้" (CR-20)

## ส่วน 2: หน้ารายการสินค้า

### 2.1 KPI

`ทั้งหมด` · `Active` · **`NPD`** (= Planned + NPD · บรรทัดรอง `ยังไม่เปิดขาย {a} · เปิดขายแล้ว {b}`) · `ขาดข้อมูลจำเป็น` · `ขาดข้อมูลที่ควรมี` · `ยังไม่เปิดใน TRCLOUD` · ทุกใบกดเพื่อกรอง

### 2.2 ตัวกรอง

- **แสดงตลอด:** ค้นหา (`Product Code / ชื่อ / Barcode`) · Status · Series · หมวดสินค้า (เลือกแบบลำดับชั้นในตัวเดียว)
- ปุ่ม **`ตัวกรองเพิ่มเติม (n)`** กดครั้งเดียวกางเป็นแถวที่สองในหน้า (ไม่เป็น Popup) จำสถานะกาง/พับ: Channel ที่ Listing · ระดับความครบถ้วน · ที่มา (`ทีม Product` / `จาก Sales`) · ใน TRCLOUD
- ตัวกรองที่ใช้อยู่เป็น Chip ใต้แถว กด × เอาออก + `ล้างทั้งหมด`

### 2.3 คอลัมน์และ Preset

- เลือกได้ทุกคอลัมน์ ยกเว้น `Product Code` และ `ชื่อสินค้า` ที่บังคับแสดงและ **ติดซ้าย** (ชื่อแสดงชื่อสั้น Tooltip ชื่อเต็ม)
- ลากเรียงลำดับคอลัมน์ในเมนูเลือกคอลัมน์
- **Preset ส่วนตัวของผู้ใช้:** `บันทึกเป็น Preset…` · เลือก Preset · `ตั้งเป็นค่าเริ่มต้นของฉัน` · ลบ · `คืนค่าตั้งต้น` · Preset ตั้งต้นของระบบ 3 ชุด: `มาตรฐาน` · `ราคา` · `ตรวจความครบถ้วน`
- เก็บแยกตามผู้ใช้ของมุมมองผู้ใช้ที่เลือก (`ui.columnPresets.<userId>.<tableId>`) · ข้อจำกัด Prototype: เก็บในเบราว์เซอร์
- สร้างเป็น Component กลาง `SP.core.components.columnPicker` ใช้ซ้ำกับตารางอื่นได้

### 2.4 จุดแก้เล็ก

- ปุ่ม `ส่งออก CSV` → `ส่งออก ▾` (Excel / CSV)
- ตัดเส้นใต้ประของช่อง Category / Sub Category / Type (ไม่ใช่ลิงก์)
- Drawer: ขนาดบรรจุแสดงตัวเลขและหน่วยบรรทัดเดียว · รูปตัวแทนเล็กลง (ไม่เกิน 96px) · แท็บ `ราคา` แสดงราคาหลักตามรอบเวลาและ Promotion Price ของสินค้านี้ (อ่านอย่างเดียว ลิงก์ไปหน้าราคา)

## ส่วน 3: หน้าแผนการเปิดตัวสินค้าใหม่ (NPD)

### 3.1 จุดประสงค์ (ใส่ในคู่มือและปุ่ม `?`)

`ติดตามสินค้าใหม่ตั้งแต่วางแผนจนเปิดตัว ทีมขายใช้ดูว่าสินค้าใหม่ใดพร้อมขายเมื่อใด ทีม Product ใช้ติดตามขั้นงานและคำขอจากทีมขาย`

### 3.2 ข้อมูลของแผน NPD (เพิ่ม)

| ฟิลด์ | หมายเหตุ |
|---|---|
| เดือนเปิดตัว | เดือนที่แน่นอน **หรือ** ไตรมาส (`Q2 2028`) สำหรับแผนที่ยังไม่ชัด |
| ขั้นงานและวันเป้าหมาย | 4 ขั้นก่อนเปิดตัว: วางแผน · สรุปแนวคิด · เตรียมผลิต · พร้อมขาย · แต่ละขั้นมีเดือนเป้าหมาย (ไม่บังคับ) · ขั้นปัจจุบัน |
| Channel / หน่วยขายที่วางแผน | + เดือนเริ่มขายต่อหน่วย (เดิม) |
| ราคา RSP ที่คาด | ไม่บังคับ |
| ผู้รับผิดชอบฝั่ง Product | ชื่อ |
| ที่มา | ทีม Product / จาก Sales |

- แผนที่ระบุเป็นไตรมาส: SKU Planning ยังเพิ่มเข้าแผนได้ แต่ล็อกเดือนก่อนไตรมาสนั้นเป็น 0 และแสดงป้าย `เดือนเปิดตัวยังไม่ยืนยัน` · Status ของสินค้าเป็น `Planned` จนกว่าจะระบุเดือน
- `เปิดตัวแล้ว` ตั้งอัตโนมัติเมื่อถึงเดือนเปิดตัว (เดิม)

### 3.3 Layout

```
แผนการเปิดตัวสินค้าใหม่ (NPD) ?                                         [ส่งออก ▾] [แก้ไข] [+ เพิ่ม NPD]
[NPD ทั้งหมด 3] [ยังไม่เปิดตัว 3 · เปิดตัวใน 3 เดือน 1] [ตาม Series …] [หน่วยขายที่ยังไม่อยู่ในแผน SKU 2 ›]
[Timeline | ตาราง]  ช่วงเวลา: [12 | 18 | 24 เดือน] ตั้งแต่ [ก.ย. 2026 ▾]  Series ▾  ขั้นงาน ▾  ที่มา ▾   ● คำขอจาก Sales 0
```

- ตัดตัวเลือกปีที่หัวข้อและ `‹ ปี 2027 ›` ออก ใช้ `ช่วงเวลา` แทน (ค่าเริ่มต้น 18 เดือนตั้งแต่เดือนปัจจุบัน) · หัวคอลัมน์แสดงปีเมื่อข้ามปี และเส้นแบ่งปี
- **คำขอจาก Sales:** แสดงเป็น Chip ในแถบเครื่องมือ (`● คำขอจาก Sales {n}`) กดแล้วกรองเฉพาะคำขอ · เมื่อ n > 0 Chip เป็นสีเน้น · ตัดการ์ดเต็มแถวเดิมและข้อความเรื่องรหัสชั่วคราว
- KPI `หน่วยขายที่ยังไม่อยู่ในแผน SKU` กดแล้วแสดงรายการ (Popover: SKU · หน่วยขาย · ลิงก์เปิด SKU Planning)

### 3.4 Timeline

- คอลัมน์ซ้าย (ติดซ้าย): รูป · ชื่อสั้น · Product Code · บรรทัดเล็ก `เปิดตัว {เดือน} · {n} หน่วยขาย · ในแผน SKU {x}/{n}`
- แถบในแต่ละแถว:
  - **ก่อนเปิดตัว:** แถบต่อกันตามขั้นงาน (สีตามขั้น) จากเดือนเป้าหมายของแต่ละขั้น · ขั้นปัจจุบันมีขอบเข้ม · ขั้นที่ไม่มีวันเป้าหมายไม่วาด
  - **เดือนเปิดตัว:** หมุด ◆ (แผนแบบไตรมาส: แถบประครอบทั้งไตรมาส + `?`)
  - **หลังเปิดตัว:** แถบจางช่วง NPD 3 เดือน ป้าย `NPD`
- ขั้นงานที่เลยวันเป้าหมายแล้วยังไม่เสร็จ แสดง ⚠ ที่แถว
- ชื่อยาวตัดขึ้น 2 บรรทัด (ไม่ตัดด้วย … บรรทัดเดียว)

### 3.5 ตาราง

คอลัมน์: SKU · Series · ขั้นงาน · เดือนเปิดตัว · Channel / หน่วยขายที่วางแผน · ในแผน SKU · ราคา RSP ที่คาด · ผู้รับผิดชอบ · ที่มา · ใน TRCLOUD

## ส่วน 4: หน้าราคา (แทนหน้าราคาขายต่อ Account)

### 4.1 โครงข้อมูล

```js
// ราคาหลัก: เปลี่ยนได้รายเดือน มีผลวันที่ 1
master.basePrices: [{ productKey, priceType: "RSP"|"TT_DEALER"|"TT_WHOLESALE", effectiveMonth, price, by, at }]

// Promotion Price: รายเดือน ระดับ Channel หรือ Sub-channel
master.promoPrices: [{ productKey, channelId, unitId|null, month, price, by, at }]
```

- ลำดับการหาราคาของ SKU × หน่วยขาย × เดือน M (ฟังก์ชันเดียว `resolvePrice(productKey, unitId, month)` ใน `calc.js` คืน `{ price, source }`):
  1. Promotion Price ของหน่วยขายนั้น เดือน M
  2. Promotion Price ของ Channel นั้น (`unitId = null`) เดือน M
  3. ราคาหลักที่มีผล ณ เดือน M: MT / ECOM / Export = `RSP` · TT = `TT_DEALER`
- ราคาหลักที่มีผล ณ เดือน M = รายการล่าสุดที่ `effectiveMonth ≤ M`
- **ย้ายข้อมูลเดิม:** ราคาต่อ Account ของ CR-18 (เช่น Juicy Pop Tint 02/05 ที่ 7-Eleven = 149) → Promotion Price ระดับหน่วยขาย ทุกเดือนของปีแผน · `rsp` และ `dealerPrice` ของสินค้า → ราคาหลัก `effectiveMonth = 2024-01`
- ประเภทราคาเพิ่มได้ภายหลังในไฟล์ตั้งค่า (เช่น TT Clearance, Export)

### 4.2 แท็บราคาหลัก

- ตัวเลือก `ราคา ณ เดือน [ก.ย. 2026 ▾]`
- ตาราง SKU (จัดกลุ่มตาม Series) × `RSP` · `TT Dealer` · `TT Wholesale`
- ช่องที่เปลี่ยนในเดือนที่เลือกมีจุดเล็ก · คลิกช่อง → Popover ประวัติราคา (เดือนที่มีผล · ราคา · ผู้บันทึก)
- โหมดแก้ไข: ปุ่ม **`+ บันทึกราคาใหม่`** → เลือกเดือนที่มีผล (เดือนปัจจุบันหรืออนาคต) → กรอกเฉพาะ SKU ที่เปลี่ยน (ตารางเดียวกัน ช่องที่แก้ไฮไลต์) หรือ **นำเข้าจาก Excel** (หน้าตรวจก่อนยืนยัน: ค่าเดิม → ใหม่) → บันทึก

### 4.3 แท็บ Promotion Price

แถบเครื่องมือ: Channel (Segmented รวม TT) · มุมมอง `รายเดือน | ภาพรวมเดือน` · Series · ค้นหา · ☐ ซ่อนหน่วยขายที่ไม่มีสินค้า Listing

- **มุมมองรายเดือน:** เลือก `ทั้ง Channel` หรือหน่วยขาย → ตาราง SKU × 12 เดือนของปีแผน (ตัวเลือกปีต่อท้ายชื่อหน้า)
- **มุมมองภาพรวมเดือน:** เลือกเดือน → ตาราง SKU × หน่วยขายของ Channel (คอลัมน์แรก `ทั้ง Channel`)
- การแสดงผลช่อง:
  - ราคาที่ได้รับมา (จาก Channel หรือราคาหลัก): **ตัวจาง** · Tooltip บอกที่มา
  - Promotion Price ที่ตั้งไว้ที่ระดับนี้: **ตัวเข้ม + พื้นอ่อน + ป้าย `−x%`** เทียบราคาหลัก
  - ไม่ได้ Listing ในหน่วยขายนั้น: **พื้นเทา ไม่มีตัวเลข** (ไม่ใช้ `–`)
- โหมดแก้ไข (ใช้ Grid กลางเดียวกับ SKU Planning): กรอกราคา · ลบค่า = กลับไปใช้ราคาที่ได้รับมา · เลือกหลายช่อง → `ตั้งราคา…` / `ลด x% จากราคาหลัก` / `คัดลอกไปเดือน…` / `คัดลอกไปหน่วยขาย…` · วางจาก Excel · Ctrl+Z
- เตือน (ไม่บล็อก): ราคาสูงกว่าราคาหลัก หรือต่ำกว่าราคาหลักเกิน 50%
- Legend: ราคาที่ได้รับมา · Promotion Price · ไม่ได้ Listing

### 4.4 ชื่อและสิทธิ์

- ชื่อเมนูและหน้า: **`ราคาและ Promotion`** · คำอธิบาย `ราคาหลักตามรอบเวลา และ Promotion Price รายเดือนของแต่ละ Channel และหน่วยขาย`
- สิทธิ์ (ส่วน 6): ราคาหลัก = ทีม Product · Promotion Price = Sales Director (ทุก Channel) และ Sales Manager / Officer (เฉพาะ Channel ในทีม)

## ส่วน 5: หน้า Listing

### 5.1 ช่วงเวลา Listing ต่อหน่วยขาย

- โครงข้อมูล: `master.listings: [{ productKey, unitId, status, fromMonth, toMonth|null, addedBy }]`
  - `status`: **`เสนอขาย`** (กำลังเสนอ Account) · **`วางขาย`** · **`ถอดแล้ว`**
  - `fromMonth` = เดือนเริ่มวางขายในหน่วยขายนั้น (แทนวันเริ่มขายเดียวต่อ SKU) · `toMonth` = เดือนสุดท้ายก่อนถอด
- ย้ายข้อมูลเดิม: Checkbox เดิม → `วางขาย` · `fromMonth` = วันเริ่มขายเดิมของ SKU (หรือเดือนเริ่มขายต่อหน่วยจากแผน NPD ถ้ามี)
- `เดือนเปิดตัว` ของสินค้า (ระดับ SKU) ยังเก็บไว้ใช้คำนวณ Status NPD · `เลิกขาย` ระดับ SKU ยังอยู่ (Discontinued = ถอดทุกหน่วย)
- **SKU Planning:** เดือนนอกช่วง `วางขาย` ของหน่วยนั้น = ล็อก 0 (แทนการใช้วันเริ่มขายเดียว) · `เสนอขาย` เพิ่มเข้าแผนได้พร้อมป้าย `ยังไม่ยืนยัน Listing`

### 5.2 Layout

```
Listing ?   ข้อมูล ณ เดือน [ก.ย. 2026 ▾]                                        [ส่งออก ▾] [แก้ไข]
[MT | TT | ECOM | Export]  ค้นหา · Series · Status · สถานะ Listing ▾ · อายุ ▾ · ☐ ไม่มียอด ≥ 3 เดือน
                                        ┌ Listing ต่อหน่วยขาย · MT ──────────────────┐
SKU (ชื่อสั้น · Code · Series)  ความครอบคลุม │ 7-Eleven   Watsons   EVEANDBOY  …        │ Clearance
Matte All Day Cushion 5g -01    8/9        │ ✓ ม.ค.24   ✓ ม.ค.24   ✓ ม.ค.24            │ –
                                           │ 2ป 8ด     ไม่มียอด 3ด  2ป 8ด              │
```

- ช่องหน่วยขาย 2 บรรทัด: สัญลักษณ์สถานะ (`✓` วางขาย · `◌` เสนอขาย · `✕` ถอดแล้ว · ว่าง = ไม่เคย Listing) + เดือนเริ่ม · บรรทัดเล็ก = อายุการขายในหน่วยนั้น หรือป้าย `ไม่มียอด {n}ด` (ใช้ `salesAge` ของ CR-26)
- ตัดพื้นสีเขียวเต็มช่อง ใช้สีเฉพาะสัญลักษณ์
- คอลัมน์ `ความครอบคลุม` = วางขาย `{x}/{จำนวนหน่วยขายที่ใช้งานใน Channel นี้}` (แทน `Listing 15 หน่วย` ที่นับข้าม Channel)
- หัวคอลัมน์หน่วยขายแสดงจำนวน SKU ที่วางขายในหน่วยนั้น
- ตัวกรอง `อายุ` และ `ไม่มียอด` ใช้นิยามเดียวกับ SKU Planning (CR-27) เพื่อใช้ **ประเมินการถอด Shelf**
- ตัดตัวกรอง `Item Type` · ตัดคอลัมน์ `วันเริ่มขาย` และ `Status 2027` แยก (Status แสดงเป็น Badge ในคอลัมน์ SKU) · ตัดคอลัมน์ `เลิกขาย` (แสดงใน Badge `Discontinued {เดือน}`)
- กล่อง `คำอธิบายสถานะและวิธีเติมยอด` ย้ายไปปุ่ม `?`
- แท็บ TT: คอลัมน์ = เขตการขาย

### 5.3 การแก้ไข (โหมดแก้ไข)

- คลิกช่อง → Popover: สถานะ (`เสนอขาย` / `วางขาย` / `ถอดแล้ว`) · เดือนเริ่ม · เดือนถอด (เมื่อถอด) · ประวัติ
- เลือกหลายช่อง (ลาก หรือ Shift+คลิก) → `วางขายตั้งแต่…` · `ถอดตั้งแต่…` · `เสนอขาย`
- ทางลัดเดิม: `เลือกทั้งแถว` · `เลือกทั้งคอลัมน์` · `ทั้ง Series ใน {หน่วยขาย}`
- ถอดสินค้าที่ยังมีแผน SKU ในเดือนหลังเดือนถอด → กล่องยืนยันแสดง `มีแผน {x} ชิ้น ({y} บาท) ในเดือนที่จะถูกล็อก` (แจ้งเท่านั้น)
- Clearance (Supply Chain) คงเดิม
- Listing ที่ Sales สร้างจาก SKU Planning (CR-20) ยังมีป้าย `Listing โดย Sales`

## ส่วน 6: หมวดสินค้าและ Series

- **ตัวกรองเหลือ:** ค้นหา · Series (เฉพาะแท็บหมวดสินค้า) · หมวดสินค้า (เฉพาะแท็บ Series) · สถานะ · ข้อมูลที่ต้องตรวจ · แถวเดียว (ตัด Category / Sub Category / Sub Series ที่ซ้ำกับคอลัมน์)
- แผงรายละเอียด:
  - ชื่อ + บรรทัดรอง `{ระดับ} · อยู่ใน {เส้นทางแม่}` (เช่น `Type · อยู่ใน Cheek › Blush`)
  - **คำเตือนย้ายขึ้นไว้ใต้ชื่อ** (เช่น `ชื่อซ้ำกับระดับบน`)
  - Type: ฟิลด์ใหม่ **`เลขนำหน้า Product Code`** (2 หลัก · ห้ามซ้ำกับ Type อื่น) + บรรทัด `รหัสถัดไป: 12250` · Type ที่ยังไม่มีเลขนำหน้าอยู่ในข้อมูลที่ต้องตรวจ
- ⚠ แสดงเฉพาะที่ระดับที่มีปัญหา (ไม่ซ้ำทั้งระดับแม่และลูก)
