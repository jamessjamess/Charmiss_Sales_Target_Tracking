## 1. โครงข้อมูล

### 1.1 ฟิลด์ของสินค้า

| ฟิลด์ | รายละเอียด |
|---|---|
| `kind` | `single` (ค่าเริ่มต้นของสินค้าเดิมทั้งหมด) หรือ `bundle` |
| `components` | เฉพาะ `bundle` · รายการ `{ skuId, qty }` · `qty` เป็นจำนวนเต็ม ≥ 1 |

### 1.2 กติกา (บังคับที่ Store)

**ส่วนประกอบ**
- ผลรวม `qty` ≥ 2
- ชิ้นส่วนต้องเป็น `kind: single`
- ห้ามมี `skuId` ซ้ำในรายการ ถ้าเพิ่มซ้ำให้รวมจำนวน
- ชิ้นส่วนต้องไม่เป็นสถานะ `Request` หรือ `Delete` ขณะสร้างหรือแก้ Bundle
- **ชุดส่วนประกอบซ้ำ:** Bundle 2 รายการที่มีชุดส่วนประกอบเหมือนกันทุกบรรทัด บันทึกได้ แต่ต้องขึ้นในข้อมูลที่ต้องตรวจ (ข้อ 2.4)

**การเปลี่ยนส่วนประกอบ**
- เปลี่ยนส่วนประกอบของ Bundle ที่มีแผน SKU แล้วได้
- ต้องถามยืนยัน `Bundle นี้มีในแผน N หน่วยขาย ความต้องการชิ้นส่วนจะคำนวณใหม่`

### 1.3 รหัสและหมวดสินค้า

**รหัส**
- ใช้ตัวสร้างรหัส 5 หลักเดิม เลขนำหน้า `9` สำหรับ Type `Bundle`
- ถ้าตัวสร้างใช้เลขนำหน้าจากตาราง Type ให้เพิ่ม Type `Bundle` ในตารางนั้น

**หมวดสินค้า**
- ระบบกำหนดหมวดสินค้าอัตโนมัติตามข้อ 0 #7
- เพิ่ม Category `Set & Bundle` → Sub Category `Bundle` → Type `Bundle` ในแท็บ Product Level

**Series**
- `SP.calc.bundleSeries(bundle)` คืน Series ของชิ้นส่วน ถ้าทุกชิ้นส่วนอยู่ Series เดียวกัน
- มิฉะนั้นคืน `Mix Series`
- ทีม Product แก้ Series เองได้ ถ้าแก้แล้วให้ใช้ค่าที่แก้

### 1.4 ฟังก์ชันใน `core/calc.js`

| ฟังก์ชัน | คืนค่า |
|---|---|
| `SP.calc.bundleComponentPrice(bundle, priceKey, month, salesUnitId)` | ผลรวม (ราคาชิ้นส่วน × qty) ตามลำดับราคาเดิมของแต่ละชิ้นส่วน |
| `SP.calc.bundleDiscount(bundle, …)` | `1 − ราคา Bundle ÷ ราคารวมชิ้นส่วน` |
| `SP.calc.componentDemand(scope)` | ต่อ SKU เดี่ยว × เดือน: `{ direct, viaBundle, total }` เป็นชิ้น |

- `direct` = จำนวนในแผนของ SKU เดี่ยวนั้น
- `viaBundle` = Σ(จำนวนชุดในแผน × qty ของชิ้นส่วนนั้น)

## 2. หน้า Bundle (Product Master)

### 2.1 เมนูและสิทธิ์

**เมนู**
- ตำแหน่ง: ต่อจาก Product List
- ตัวอักษรเมนู `B`
- ชื่อ `Bundle`

**สิทธิ์**
- เพิ่ม Page key ใหม่
- ค่าเริ่มต้น: ทีม Product = แก้ไข · บทบาทอื่น = ดู

**หัวหน้า**
- `Bundle` · ปุ่ม `?` · `ส่งออก ▾` · `แก้ไข`
- ไม่มีคำอธิบายใต้หัวข้อ ตามมาตรฐาน Product Master

### 2.2 แท็บ

- `รายการ Bundle | ความต้องการชิ้นส่วน`

### 2.3 แท็บรายการ Bundle

**การ์ด KPI**

| การ์ด | ค่า |
|---|---|
| Bundle ทั้งหมด | ทุกสถานะ ยกเว้น `Delete` |
| Active | สถานะ `Active` |
| อยู่ในแผน | Bundle ที่มีจำนวนในแผน SKU ปีแผนอย่างน้อย 1 หน่วยขาย |
| ชิ้นส่วนที่ต้องตรวจ | Bundle ที่มีชิ้นส่วนสถานะ `Discontinued` · `Clearance` · `Delete` |

**ตัวกรอง**
- ค้นหารหัส / ชื่อ (ค้นจากรหัสหรือชื่อชิ้นส่วนได้)
- Status (ค่าเริ่มต้น `ไม่รวม Delete`)
- Series
- ชิ้นส่วน (เลือก SKU เดี่ยว เพื่อดูว่าอยู่ใน Bundle ใดบ้าง)

**ตาราง**

| คอลัมน์ | รายละเอียด |
|---|---|
| Product Code | เช่น `90200` |
| ชื่อ Bundle | |
| Status | ป้ายสถานะมาตรฐาน |
| ส่วนประกอบ | Chip `12130 × 1` · `12140 × 1` · Tooltip ของ Chip แสดงชื่อและสถานะชิ้นส่วน · ชิ้นส่วนสถานะผิดปกติใช้ Chip สีเหลือง |
| จำนวนชิ้น / ชุด | ผลรวม qty |
| ราคารวมชิ้นส่วน (RSP) | จาก `bundleComponentPrice` ของเดือนปัจจุบัน |
| RSP Bundle | ราคาหลักของ Bundle |
| ส่วนลด Bundle | % (ติดลบ = Bundle แพงกว่าซื้อแยก แสดงสีแดง) |
| Series | |
| แผนปีแผน (ชุด) | ผลรวมทุกหน่วยขาย |
| จัดการ | ปุ่ม `›` เปิด Drawer |

### 2.4 Drawer Bundle (กว้าง 50%)

**ส่วนข้อมูลทั่วไป**
- ใช้รูปแบบ Drawer สินค้าเดิม ได้แก่ รหัส · ชื่อ · ชื่อย่อ · Status · หมวดสินค้า (ระบบกำหนด) · Series · รูป

**ส่วนประกอบ**
- ตารางแก้ไขได้: ชิ้นส่วน (ค้นหา SKU เดี่ยว) · ชื่อ · Status · จำนวน (ปุ่ม − / + และช่องกรอก) · ราคา RSP ต่อชิ้น · รวม · ปุ่ม `นำออก`
- ปุ่ม `+ เพิ่มชิ้นส่วน`
- แถวรวมท้ายตาราง: `จำนวนชิ้นรวม N · ราคารวมชิ้นส่วน X บาท · RSP Bundle Y บาท · ส่วนลด Z%`
- ข้อความเตือนสีแดงใต้ตารางเมื่อผิดกติกาข้อ 1.2 และปุ่ม `บันทึก` ใช้ไม่ได้

**แท็บย่อยอื่นของ Drawer**
- `ราคา` · `Listing และวงจรสินค้า` · `ประวัติการแก้ไข` ใช้ร่วมกับสินค้าเดี่ยว

**ปุ่ม `+ สร้าง Bundle`**
- อยู่ที่หัวตารางในโหมดแก้ไข
- เปิด Drawer เปล่า
- สถานะเริ่มต้น `Planned`

**ข้อมูลที่ต้องตรวจ (Component `dataCheck`)**
- ชิ้นส่วนสถานะ `Discontinued` / `Clearance` / `Delete`
- Bundle ที่มีชุดส่วนประกอบซ้ำกัน
- ส่วนลด Bundle ติดลบ
- Bundle ที่ไม่มี RSP

### 2.5 แท็บความต้องการชิ้นส่วน

**ตัวกรอง**
- ปี (`yearPicker`) · Channel · หน่วยขาย · Series

**ตาราง**
- แถว = SKU เดี่ยวที่เป็นชิ้นส่วนของ Bundle อย่างน้อย 1 รายการ
- คอลัมน์ = ม.ค.–ธ.ค. และ รวมปี
- แต่ละ SKU มี 3 บรรทัด: `ขายเดี่ยว` · `ผ่าน Bundle` · `รวม` (ตัวหนา)
- กางแถว `ผ่าน Bundle` เพื่อดูแยกราย Bundle ได้
- ใช้ `componentDemand` · หน่วย `ชิ้น`

**หมายเหตุท้ายตาราง**
- `จำนวนผ่าน Bundle ใช้ดูความต้องการสินค้าเท่านั้น ยอดขายนับที่ Bundle ไม่นับซ้ำที่ชิ้นส่วน`

## 4. SKU Planning

**แถว Bundle**
- แสดงในแผนเหมือน SKU ทั่วไป
- ป้าย `Bundle` ต่อท้ายชื่อ
- บรรทัดใต้ชื่อเป็น `90200 · 12130 × 1 + 12140 × 1` (ตัดด้วย `…` เมื่อยาว · Tooltip แสดงเต็ม)
- จำนวนในแถว Bundle มีหน่วย `ชุด` แสดงเป็นข้อความเทาเล็กที่หัวแถว

**แถวรวมแผน (ชิ้น)**
- แถวรวมแผน (ชิ้น) ท้ายตาราง นับจำนวนชุดของ Bundle เป็น 1 ต่อชุด (ตรงกับยอดขาย)
- เพิ่ม Tooltip `รวม Bundle N ชุด (เท่ากับ M ชิ้นส่วน)`

**ประเภทสินค้าในแผน**
- ใช้ `planTypeOf` ตามสถานะของ Bundle เอง (CR-34 / CR-35)

**Dialog เพิ่มสินค้าในแผน**
- แท็บ 1 และ 2 แสดง Bundle ด้วย มีป้าย `Bundle`
- เพิ่มตัวกรอง `ประเภทสินค้า`

**Tooltip ชิ้นส่วนที่ต้องตรวจ**
- ถ้าชิ้นส่วนของ Bundle ในแผนมีสถานะ `Delete` ให้แถว Bundle แสดงเส้นขอบเหลือง
- Tooltip `ชิ้นส่วน <รหัส> สถานะ Delete`
- ไม่ล็อกแถว

## 7. Test (`node tests/run.js`)

**กติกา Store**
- ปฏิเสธ Bundle ที่มีผลรวม qty < 2
- ปฏิเสธ Bundle ซ้อน Bundle
- ปฏิเสธชิ้นส่วนสถานะ `Request` หรือ `Delete`
- เพิ่ม `skuId` ซ้ำแล้วรวมเป็นบรรทัดเดียว

**รหัส**
- Bundle ใหม่ได้รหัสขึ้นต้นด้วย `9`
- รหัสไม่ซ้ำกับสินค้าเดิม

**`bundleSeries`**
- 90100 ได้ `Charming Lab`
- Bundle ที่ชิ้นส่วนต่าง Series ได้ `Mix Series`

**`bundleComponentPrice`**
- 90100 ได้ 59 × 2 = 118
- ส่วนลด = 1 − 109 ÷ 118

**`componentDemand`**
- 12130 เดือน มี.ค. 2027 `viaBundle` = 150 × 2 + 200 × 1 = 500
- `total` = `direct` + `viaBundle`

**ยอดขายไม่นับซ้ำ**
- Net Sales รวมแผนของหน่วยขาย = Σ Net Sales ของทุกแถวในแผน รวม Bundle
- ไม่มีการบวกยอดของชิ้นส่วนเพิ่ม

**Feature Flag**
- ปิด `bundle` แล้วเมนู Bundle หาย
- แถว Bundle ไม่แสดงใน SKU Planning
- ยอดรวมแผนไม่นับ Bundle

**ตัวเลขเดิม**
- หน่วยขายที่ไม่มี Seed Bundle มียอดเท่ากับก่อนทำ CR
