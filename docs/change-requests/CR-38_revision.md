## 1. โครงข้อมูล

### 1.1 Entity

| Entity | ฟิลด์หลัก |
|---|---|
| `revision` | `id` · `planYear` · `seq` (1, 2, …) · `name` (`2027 R2`) · `status` (`draft` / `submitted` / `locked`) · `effectiveMonth` · `basedOn` (id ของรอบก่อน) · `reason` · `openedBy/At` · `submittedBy/At` · `lockedBy/At` · `returnNote` · `history[]` (ทุกการเปลี่ยนสถานะ: ผู้ทำ เวลา ข้อความ) |
| `revisionData` | ข้อมูลของ 4 ขั้นต่อรอบ: Total · เป้าหมาย Channel · เป้าหมายหน่วยขาย × เดือน · จำนวนแผน SKU × หน่วยขาย × เดือน |
| `revisionSnapshot` | สร้างตอน Lock: ค่าที่คำนวณแล้ว (Sale Amount · Net Sales ต่อแถว) · ราคาที่ใช้ต่อ SKU × หน่วยขาย × เดือน · GP / Fee · ชื่อและสถานะสินค้า · ชื่อหน่วยขาย · ผู้รับผิดชอบ ณ เดือนนั้น · ยอดอ้างอิง L12M |

### 1.2 การอ่านข้อมูล

- ข้อมูลของ Sales Planning ทั้งหมดต้องอ่านผ่าน Revision ที่เลือก
- ให้ปรับ Store ให้มีฟังก์ชันกลาง `SP.revision.current()` และ `SP.revision.get(id)` และให้ทุกหน้าใน Sales Planning อ่านผ่านฟังก์ชันนี้
- **รอบ `ร่าง`:** คำนวณสดจาก Master ปัจจุบันเหมือน Phase 1
- **รอบ `รอ Lock`:** คำนวณสดเช่นกัน แต่ห้ามแก้
- **รอบ `Lock แล้ว`:** อ่านจาก `revisionSnapshot` เท่านั้น ห้ามคำนวณใหม่จาก Master

### 1.3 ข้อบังคับห้ามแก้ย้อนหลัง (Store)

**ฟังก์ชันตรวจ** ทุกคำสั่งเขียนข้อมูลของ Sales Planning ต้องผ่าน `SP.revision.assertWritable(revisionId, month)` ซึ่งจะปฏิเสธเมื่อ
1. รอบนั้นสถานะไม่ใช่ `draft`
2. `month` < `effectiveMonth` ของรอบนั้น
3. `month` ≤ เดือนปิดล่าสุดตามเวลาปัจจุบัน (ตาม `DEMO_CURRENT_MONTH`)

**การเขียนระดับทั้งปี** (เช่น Total)
- ตรวจว่าค่าของเดือนที่ล็อกไม่เปลี่ยน
- ส่วนต่างทั้งหมดต้องไปลงในเดือนที่เปิดเท่านั้น

**ข้อความปฏิเสธ** (อยู่ใน `content.js`)
- `แก้ไม่ได้: <ชื่อรอบ> Lock แล้ว`
- `แก้ไม่ได้: เดือน <เดือน> อยู่ก่อนเดือนที่มีผลของรอบนี้`

**ข้อมูลที่ Lock แล้ว**
- `revisionSnapshot` และ `revisionData` ของรอบที่ Lock แล้วเป็น Object แบบแช่แข็ง (`Object.freeze` แบบลึก)
- ไม่มีฟังก์ชันใดในระบบที่ลบหรือแก้รอบที่ Lock ได้
- ปุ่ม `รีเซ็ตข้อมูล` เป็นข้อยกเว้นเดียว เพราะล้างทั้ง Session และกลับไปที่ Seed

### 1.4 เดือนที่มีผล (`effectiveMonth`)

**R1**
- เดือนแรกของปีแผน (ม.ค. 2027)

**รอบถัดไป**
- ตั้งตอนเปิดรอบ
- ค่าเริ่มต้นคือเดือนถัดจากเดือนปัจจุบัน แต่ไม่ก่อนเดือนแรกของปีแผน
- ห้ามเลือกเดือนที่ ≤ เดือนปิดล่าสุด
- **ใน Prototype:** ผู้ดูแลระบบและ Management เลือกเดือนในปีแผนได้ เพื่อจำลองการปรับเป้ากลางปี เช่น เปิด R2 มีผล เม.ย. 2027
- **ในระบบจริง:** กำหนดเป็นเดือนถัดไปเสมอ (บันทึกใน DECISIONS)

**เดือนก่อนเดือนที่มีผล**
- ค่าของทั้ง 4 ขั้นคัดลอกจากรอบก่อนและล็อก

- `Revision List` · ปุ่ม `?` · ตัวเลือกปีแผน (`yearPicker`) · `ส่งออก ▾`
- ปุ่มตามสิทธิ์และสถานะ (ส่วนที่ 3.4)

### 3.3 แถบสถานะรอบปัจจุบัน (การ์ดบนสุด)

```
2027 R2 · ร่าง · มีผลตั้งแต่ เม.ย. 2027
เปิดโดย <ชื่อ> เมื่อ <วันที่> · เหตุผล: <ข้อความ>
Total Target 126,000,000 บาท (R1 120,000,000 · +6,000,000 · +5.0%)
ตรวจก่อนเสนอ Lock:  [ครบ] Total = Channel   [ครบ] Channel = หน่วยขาย   [ขาด] หน่วยขาย = รายเดือน   [ขาด 3 หน่วยขาย] แผน SKU ครบเป้า
```

**รายการตรวจก่อนเสนอ Lock**
- 3 ข้อแรกต้อง `ครบ` จึงเสนอ Lock ได้
- ข้อแผน SKU เป็นคำเตือน ไม่บังคับ และบันทึกสถานะไว้ใน Snapshot
- แต่ละข้อคลิกแล้วพาไปหน้าที่ต้องแก้
- ใช้ฟังก์ชันตรวจความครบถ้วนเดิมของแต่ละขั้น

### 3.4 ปุ่มคำสั่ง

| สถานะรอบล่าสุด | ปุ่ม | ผู้ใช้ | ผล |

## 4. ตัวเลือก Revision ใน Sales Planning

### 4.1 ตัวเลือก

- แทนตัวเลือกปีที่หัวหน้าทุกหน้าใน Sales Planning (Annual Target · Sub-channel Allocation · SKU Planning · Plan Summary)
- รูปแบบ: `2027 · R2 ร่าง ▾`
- รายการในตัวเลือกจัดกลุ่มตามปี แต่ละรอบแสดงป้ายสถานะ
- **ค่าเริ่มต้น:** รอบ `ร่าง` หรือ `รอ Lock` ถ้ามี มิฉะนั้นใช้รอบ Lock ล่าสุด
- การเลือกใช้ร่วมกันทุกหน้าใน Sales Planning (เก็บใน Session)

### 4.2 แถบสถานะใต้หัวหน้า

| รอบที่เลือก | แถบ |
|---|---|
| `ร่าง` | สีเหลืองอ่อน: `2027 R2 · ร่าง · แก้ไขได้ตั้งแต่ เม.ย. 2027 · เดือนก่อนหน้าใช้ค่าจาก R1` |
| `รอ Lock` | สีเหลือง: `2027 R2 · รอ MD Lock · ดูอย่างเดียว` |
| `Lock แล้ว` | สีเทา: `2027 R1 · Lock แล้ว เมื่อ <วันที่> โดย <ชื่อ> · ดูอย่างเดียว` + ลิงก์ `ดูรอบปัจจุบัน` |

- แถบนี้ใช้ความสูงไม่เกิน 1 บรรทัด
- ต้องไม่ทำให้หน้าใดต้องเลื่อนที่ 1920×1080

### 4.3 เดือนที่ล็อกในรอบ `ร่าง`

- ทุกตารางรายเดือน (Sub-channel Allocation · SKU Planning) แสดงเดือนก่อน `effectiveMonth` เป็นพื้นเทาลายเส้นบาง
- ช่องเป็นอ่านอย่างเดียว
- หัวคอลัมน์มีข้อความเล็ก `ล็อก`

**Annual Target**
- ช่อง Total และ Channel ยังแก้ได้
- แสดงบรรทัดเล็กใต้ช่อง `ส่วนที่ล็อก (ม.ค.–มี.ค.) X บาท · ปรับได้ใน เม.ย.–ธ.ค.`
- ห้ามตั้งค่าเป้าหมายต่ำกว่าส่วนที่ล็อก

**คำสั่งปรับทั้งหมด**
- `ปรับทั้งหน่วยขาย ±%` · `ปรับให้ครบตามเป้าหมาย` · การกระจายรายเดือนอัตโนมัติ ทำงานเฉพาะเดือนที่เปิด

### 4.4 รอบที่ Lock แล้วและรอบ `รอ Lock`

- ทุกหน้าเป็นโหมดดู ไม่มีปุ่ม `แก้ไข`
- ปุ่มสร้างหรือเพิ่มต่าง ๆ ซ่อน

**Plan Summary**
- รอบ `ร่าง` และ `รอ Lock` ใช้ลายน้ำ `ฉบับร่าง` และ `รอ Lock` ตามลำดับ
- รอบ `Lock แล้ว` ไม่มีลายน้ำ
- หัวรายงานแสดง `2027 R1 · Lock แล้ว <วันที่> โดย <ชื่อ MD>`

**แท็บติดตามสถานะของ Plan Summary**
- เพิ่มส่วนสถานะของ Revision ปัจจุบัน (ข้อมูลเดียวกับข้อ 3.3)

## 5. หน้า Revision Compare

### 5.1 ตัวเลือก

```
เปรียบเทียบ  [2027 R1 ▾]  กับ  [2027 R2 ร่าง ▾]   ระดับ [Channel ▾]   ตัวชี้วัด [Net Sales ▾]   มุมมอง [ทั้งปี | รายเดือน]   Channel [ทั้งหมด ▾]
```

**Revision A และ B**
- เลือกรอบใดก็ได้ทุกปีแผน รวมรอบ `ร่าง`
- ค่าเริ่มต้น A = รอบ Lock ล่าสุด · B = รอบปัจจุบัน
- ถ้ามีรอบเดียว ให้เลือก A ได้อย่างเดียว และแสดงข้อความ `ต้องมีอย่างน้อย 2 Revision`
- ปุ่ม `สลับ A ⇄ B`

**ระดับ**
- `Total` · `Channel` · `หน่วยขาย` · `Series` · `SKU`
- SKU ใช้ได้เมื่อเลือก Channel หรือหน่วยขายแล้ว เพื่อไม่ให้ตารางยาวเกิน

**ตัวชี้วัด**
- `Net Sales` (ค่าเริ่มต้น) · `Sale Amount` · `จำนวนชิ้น`
- จำนวนชิ้นใช้ได้เฉพาะระดับ Series และ SKU

**มุมมอง**
- ทั้งปี / รายเดือน

### 5.2 ตาราง

**มุมมองทั้งปี**

| คอลัมน์ | รายละเอียด |
|---|---|
| ชื่อแถว | ตามระดับ |
| A | ค่า |
| B | ค่า |
| ส่วนต่าง | B − A · บวกสีเขียว ลบสีแดง |
| % | ส่วนต่าง ÷ A |
| แท่งเทียบ | 2 แท่งซ้อนแนวนอน A (เทา) · B (สีหลัก) สเกลจริงเริ่ม 0 ค่าสูงสุดเดียวกันทั้งตาราง |

**มุมมองรายเดือน**
- แต่ละแถวมี 3 บรรทัด: A · B · ส่วนต่าง
- คอลัมน์ ม.ค.–ธ.ค. + รวม
- เดือนก่อน `effectiveMonth` ของรอบที่ใหม่กว่าเป็นพื้นเทา เพื่อให้เห็นว่าเปลี่ยนไม่ได้ ส่วนต่างต้องเป็น 0

**ทั่วไป**
- แถวรวมท้ายตาราง
- เรียงตามค่าสัมบูรณ์ของส่วนต่างมากไปน้อยเป็นค่าเริ่มต้น
- ระดับ Channel และหน่วยขายมีลิงก์กางลงระดับถัดไป

### 5.3 กราฟ

- **กราฟรายเดือน:** เส้น A (เทา ประ) · เส้น B (สีหลัก) · แท่งส่วนต่างบางใต้เส้น (เขียว/แดง) · เส้นแนวตั้งที่ `effectiveMonth` ของรอบที่ใหม่กว่า พร้อมป้าย `มีผล เม.ย.`
- แกน Y เริ่ม 0 ตามมาตรฐาน

### 5.4 การคำนวณและส่งออก

- `SP.calc.compareRevisions(aId, bId, { level, metric, view, filter })` คืนแถวสำหรับตารางและกราฟ
- รอบ Lock อ่านจาก Snapshot · รอบอื่นคำนวณสด
- ส่งออกตารางเปรียบเทียบตามตัวเลือกปัจจุบัน

## 6. ปุ่มรีเซ็ตข้อมูลและ Seed

**ปุ่ม `รีเซ็ตข้อมูล`** เปลี่ยนเป็นเมนู 2 ตัวเลือก

| ตัวเลือก | ผล |
|---|---|
| `ข้อมูลตั้งต้น` | เหมือนเดิม · มีรอบเดียว `2027 R1 ร่าง` · ทุกขั้นแก้ได้ทุกเดือน (Phase 1 เดิม) |
| `ข้อมูลตัวอย่าง Revision` | `2027 R1 Lock แล้ว` (Lock 15 ธ.ค. 2026 โดย MD · จากข้อมูลตั้งต้น) + `2027 R2 ร่าง` (มีผล เม.ย. 2027 · เหตุผล `ECOM โตเกินคาดไตรมาสแรก`) |

**การเปลี่ยนแปลงของ R2 ในข้อมูลตัวอย่าง**
- **Total:** 120 → 123 ล้านบาท
- **ECOM:** +4 ล้าน กระจายในหน่วยขาย Shopee / Lazada / Tiktok ตามสัดส่วนเดิม ช่วง เม.ย.–ธ.ค.
- **MT:** −1 ล้าน ที่ Watsons ช่วง เม.ย.–ธ.ค.
- แผน SKU ไม่เปลี่ยน จึงเห็นคงเหลือ ขาด/เกิน ในรอบใหม่
