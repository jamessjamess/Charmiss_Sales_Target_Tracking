## ส่วน 1: รูปแบบร่วมของตารางสิทธิ์

### 1.1 Component กลาง

- สร้าง `SP.core.components.permissionCell(level, scope, kind, options)` ใช้ทั้งหน้า Permissions และ Users
- สร้าง `SP.core.components.permissionLegend()` แสดง Legend บรรทัดเดียว

### 1.2 การแสดงระดับสิทธิ์ (ไม่มีพื้นสีในช่อง)

| ค่า | การแสดงผล |
|---|---|
| แก้ไข (ทุก Channel) | `แก้ไข` ตัวหนา สี `--brand` |
| แก้ไข (เฉพาะทีม) | `แก้ไข` ตัวหนา สี `--brand` + ต่อท้ายตัวเล็กสีจาง `เฉพาะทีม` |
| ดู | `ดู` น้ำหนักปกติ สี `--text-muted` |
| ไม่เห็น | ช่องว่าง (ไม่มีข้อความ ไม่มีพื้นเทา) |
| ปุ่มเฉพาะ (action) อนุญาต | `อนุญาต` ตัวหนา สี `--brand` (+ `เฉพาะทีม` ถ้ามี) |
| ปุ่มเฉพาะ ไม่อนุญาต | ช่องว่าง |

- ข้อความจัดกึ่งกลางในช่อง · Hover ช่องแสดงพื้นจางทั้งแถวและทั้งคอลัมน์ เพื่อไล่ตาได้ง่าย
- Legend (ขวาของแถบเครื่องมือ): `แก้ไข` · `ดู` · `ว่าง = ไม่เห็น` แสดงด้วยรูปแบบจริงของแต่ละค่า
- ตัดจุดที่มุมช่อง (ต่างจากค่าตั้งต้น) ออก

### 1.3 โครงตาราง

- คอลัมน์แรก (ติดซ้าย) = ชื่อหน้า · หัวตารางติดบน
- แถวหัวกลุ่ม Module (`SALES PLANNING` ฯลฯ) พับได้ ตัวพิมพ์ใหญ่เล็ก สีจาง เหมือนเมนูข้าง
- แถวสิทธิ์ย่อยย่อหน้า ตัวเล็กสีจาง ไม่มีสัญลักษณ์ `└`
- กลุ่ม `ทุกหน้า` เปลี่ยนชื่อเป็น **`ทั้งระบบ`**
- ความสูงแถวสม่ำเสมอ ประมาณ 40px · เส้นแบ่งแถวจาง ไม่มีเส้นแบ่งคอลัมน์

## ส่วน 2: หน้า Permissions (รวมการจัดการบทบาท)

### 2.1 หัวหน้า

- หัวข้อ `Permissions` + ปุ่ม `?` · คำอธิบายบรรทัดเดียว: `สิทธิ์ของแต่ละบทบาทในแต่ละหน้า`
- **ตัด** ข้อความ `(หน้าที่ ไม่เห็น ไม่แสดงในเมนูข้าง)` และข้อความเรื่องสิทธิ์ฝั่งหน้าจอ (ย้ายไปคู่มือ ส่วน 4)
- ปุ่มขวา: `ประวัติการแก้ไข ▾` · `ส่งออก ▾` · `แก้ไข`

### 2.2 แถบเครื่องมือ

- `Module [ทุก Module ▾]` · `บทบาท [ทุกบทบาท ▾]` (เลือกหลายค่า) · Legend (ขวา)
- **ตัด** Checkbox `เฉพาะที่ต่างจากค่าตั้งต้น`

### 2.3 หัวคอลัมน์บทบาท

```
Sales Manager  ⋯
3 คน
```

- บรรทัด 1: ชื่อบทบาท + ปุ่ม `⋯` · บรรทัด 2: จำนวนผู้ใช้ตัวเล็ก คลิกแล้วเปิดหน้า Users ที่กรองบทบาทนั้น
- **ตัด** `เห็น x หน้า · แก้ไข y หน้า`
- บทบาทที่สร้างเองมี Chip เล็ก `สร้างเอง` ต่อท้ายชื่อ
- คอลัมน์สุดท้าย (โหมดแก้ไข): ปุ่ม **`+ เพิ่มบทบาท`** → แผงด้านข้าง: ชื่อ · คำอธิบาย · คัดลอกสิทธิ์จาก (ไม่บังคับ) · หน้าเริ่มต้น

### 2.4 เมนู `⋯` ของบทบาท (แทนหน้า Roles เดิม)

| กลุ่ม | รายการ | โหมด |
|---|---|---|
| ข้อมูลบทบาท | แก้ชื่อและคำอธิบาย · ตั้งหน้าเริ่มต้น · เลื่อนไปซ้าย · เลื่อนไปขวา | แก้ไข |
| สิทธิ์ | ตั้งทั้งคอลัมน์เป็น… · คัดลอกสิทธิ์จากบทบาท… · คืนค่าตั้งต้นของบทบาทนี้ | แก้ไข |
| อื่นๆ | ดูตัวอย่างในมุมมองนี้ · ดูรายชื่อผู้ใช้ | ทุกโหมด |
| อันตราย | ลบบทบาท (เฉพาะบทบาทที่สร้างเองและไม่มีผู้ใช้) | แก้ไข |

- `แก้ชื่อ`, `ตั้งหน้าเริ่มต้น`, `เพิ่มบทบาท` เปิดแผงด้านข้างเดียวกัน (ฟอร์มสั้น)
- ลำดับบทบาทใช้กับคอลัมน์ในหน้านี้ ตัวเลือกมุมมองผู้ใช้ และหน้า Users
- `คืนค่าตั้งต้นทั้งหมด` อยู่ในเมนู `แก้ไข` ของหัวหน้า (โหมดแก้ไข)

### 2.5 การแก้ไขช่อง

- โหมดแก้ไข: คลิกช่อง → ตัวเลือกแบบปุ่มกลุ่มแสดงในช่อง (Popover เล็กชิดช่อง):
  - หน้า: `ไม่เห็น | ดู | แก้ไข` และเมื่อหน้ารองรับขอบเขต แถวที่สอง `ทุก Channel | เฉพาะทีม`
  - ปุ่มเฉพาะ: `ไม่อนุญาต | อนุญาต` (+ ขอบเขตถ้ารองรับ)
  - กดตัวเลือกแล้วปิดทันที (ไม่มีปุ่มยืนยันในช่อง)
- คีย์บอร์ด: ลูกศรเลื่อนช่อง · `1` ไม่เห็น · `2` ดู · `3` แก้ไข · `T` สลับเฉพาะทีม
- เมนูที่หัวแถว (คลิกชื่อหน้า ในโหมดแก้ไข): `ตั้งทั้งแถวเป็น…`
- ช่องที่แก้ในรอบนี้ (ยังไม่บันทึก) มีขอบล่างสี `--brand` บาง
- กฎป้องกันเดิมของ CR-21 ข้อ 5 และกฎสิทธิ์ย่อยแบบปุ่มคำสั่ง / ส่วนของหน้าที่ตกลงไว้ ยังใช้ครบ · สรุปผลกระทบก่อนบันทึกยังคงไว้

## ส่วน 3: หน้า Users

### 3.1 หัวหน้า

- หัวข้อ `Users` + ปุ่ม `?` · คำอธิบาย: `บทบาทของผู้ใช้และสิทธิ์ที่มีผลจริง`
- ตัดข้อความเรื่องสิทธิ์ฝั่งหน้าจอ
- ปุ่มขวา: `ประวัติการแก้ไข ▾` · `ส่งออก ▾` · `แก้ไข` · `+ เพิ่มผู้ใช้` (โหมดแก้ไข)

### 3.2 แถบเครื่องมือ

`[ค้นหาชื่อ]` · **`Module [Sales Planning ▾]`** · `บทบาท ▾` · `Channel ▾` · `สถานะ [ใช้งาน ▾]` · Legend

- Module เป็นตัวเลือกเดี่ยว (ไม่มี `ทุก Module`) กำหนดคอลัมน์สิทธิ์ · ค่าเริ่มต้น `Sales Planning` · จำค่าที่ `ui.usersModule`
- สถานะค่าเริ่มต้น `ใช้งาน`

### 3.3 ตาราง

```
ชื่อ               บทบาท             ทีม        Annual Target  Sub-channel Allocation  SKU Planning        Plan Summary
SALES MANAGER · 3 คน
อนันต์ ศรีสว่าง     Sales Manager     MT                        ดู                      แก้ไข เฉพาะทีม       ดู
```

- คอลัมน์ติดซ้าย: ชื่อ · บทบาท · ทีม
- คอลัมน์สิทธิ์ = หน้าของ Module ที่เลือก รวมแถวสิทธิ์ย่อยเป็นคอลัมน์ย่อยใต้หน้า (เช่น `SKU Planning` › `สร้าง NPD`) · ใช้ `permissionCell` แบบเดียวกับหน้า Permissions
- ช่องสิทธิ์ **อ่านอย่างเดียว** เป็นสิทธิ์หลังรวมทุกบทบาทของคนนั้น · Hover แสดง `ได้จากบทบาท: {ชื่อบทบาท}`
- จัดกลุ่มตามบทบาท (ตามลำดับบทบาท) หัวกลุ่มพับได้ `SALES OFFICER · 9 คน` · คนที่มีหลายบทบาทอยู่ในกลุ่มของบทบาทแรก และแสดง Chip บทบาทอื่นในคอลัมน์บทบาท
- คอลัมน์ทีม: `MT · Manager` · `TT · Officer` (หลายค่าได้) คลิกแล้วเปิด Drawer ของคนนั้นในหน้าบุคลากรและทีม (ถ้าเป็นบุคลากร) · ไม่มีทีม = ว่าง
- ผู้ใช้ที่ปิดใช้งาน: ตัวอักษรจางทั้งแถว ช่องสิทธิ์ว่าง (ไม่มีสิทธิ์)
- ตัดคอลัมน์ `สถานะ` แบบ Pill (ใช้ตัวกรองสถานะ + แถวจางแทน)
- ชื่อไม่ใช้เส้นใต้ แสดงเป็นลิงก์เมื่อ Hover

### 3.4 แก้ไข

- โหมดแก้ไข: คอลัมน์บทบาทคลิกแล้วเลือกบทบาทได้หลายค่า (Popover รายการบทบาทพร้อม Checkbox) · สิทธิ์ในแถวเปลี่ยนตามทันที
- `+ เพิ่มผู้ใช้`: ชื่อ · เชื่อมกับบุคลากร (ไม่บังคับ เลือกจากหน้าบุคลากรและทีม) · บทบาท
- ปิด / เปิดใช้งาน: ในเมนูหัวแถว หรือใน Drawer

### 3.5 Drawer ผู้ใช้

แท็บ `ข้อมูล` (ชื่อ · บทบาท · ทีม · หน้าเริ่มต้นที่มีผล · สถานะ) · `สิทธิ์ที่มีผลจริง` (ทุก Module ใช้ `permissionCell` และบอกบทบาทต้นทาง) · `ประวัติ`

## ส่วน 4: ย้ายข้อมูลบทบาทไปคู่มือ และปิดหน้า Roles

- ตั้งหน้า `Roles` เป็น `visible: false` (ห้ามลบไฟล์) · ลิงก์เดิมพาไปหน้า Permissions
- เมนู ROLE MANAGEMENT เหลือ **Permissions · Users**
- **คู่มือการใช้งาน** แท็บ `ภาพรวมและลำดับงาน` ส่วน `บทบาทและหน้าที่` (สร้างจากข้อมูลจริง): คอลัมน์ `บทบาท · คำอธิบาย · แก้ไขได้ที่ · หน้าเริ่มต้น · จำนวนผู้ใช้` · บทบาทที่สร้างเองแสดงด้วย
- **คู่มือ** ส่วน `สำหรับการทดสอบ` เพิ่มบรรทัด: `สิทธิ์ใน Prototype ใช้ซ่อนเมนูและปุ่มบนหน้าจอเท่านั้น ระบบจริงต้องตรวจสิทธิ์ที่ Backend` (ข้อความนี้แสดงที่เดียวในระบบ)
- ตรวจทั้งระบบว่าไม่มีข้อความเรื่องสิทธิ์ฝั่งหน้าจอซ้ำในหน้าอื่น

## Test (`node tests/run.js`)

1. `permissionCell`: EDIT + TEAM → ข้อความ `แก้ไข` และ `เฉพาะทีม` · VIEW → `ดู` · NONE → ว่าง · action อนุญาต → `อนุญาต`
2. หน้า Permissions ไม่มี `เห็น x หน้า`, ไม่มี Checkbox ต่างจากค่าตั้งต้น, ไม่มีสัญลักษณ์ ✓ ✕ – ในตาราง
3. เมนู `⋯` ของบทบาท: แก้หน้าเริ่มต้นของ Sales Officer → สลับเป็น Sales Officer แล้วไปหน้าที่ตั้ง
4. `+ เพิ่มบทบาท` คัดลอกสิทธิ์จาก Sales Officer → คอลัมน์ใหม่มีสิทธิ์เท่ากัน และมี Chip `สร้างเอง`
5. ลบบทบาทที่มีผู้ใช้ → ไม่ยอมรับ · ลบบทบาทตั้งต้น → ไม่มีตัวเลือกลบ
6. หน้า Users Module = Product Master → คอลัมน์เป็น 5 หน้าของ Product Master · ผู้ใช้ 2 บทบาทได้สิทธิ์สูงสุด และ Hover บอกบทบาทต้นทาง
7. เปลี่ยนบทบาทของผู้ใช้ในหน้า Users → ช่องสิทธิ์ในแถวเปลี่ยนทันที
8. หน้า Roles ไม่อยู่ในเมนู · ลิงก์เดิมพาไป Permissions
9. คู่มือแสดงตารางบทบาทพร้อมคำอธิบายและหน้าเริ่มต้นจากข้อมูลจริง
