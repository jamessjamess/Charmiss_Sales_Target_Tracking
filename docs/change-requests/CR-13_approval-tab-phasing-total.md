## 1. ลำดับแท็บในขั้นที่ 4

- ลำดับใหม่: **`รายงานสรุปแผน` | `ติดตามสถานะ (n)`**
- เปิดแท็บ `รายงานสรุปแผน` เป็นค่าเริ่มต้นเสมอ (ยกเลิกกฎเดิมที่เปลี่ยนแท็บเริ่มต้นตามสถานะ Baseline) ยังจำแท็บล่าสุดที่ `ui.summaryTab` ภายใน Session
- `n` = จำนวนหน่วยขายที่มีประเด็น (ตัวเดียวกับไอคอนในเมนูข้าง) ถ้าเป็น 0 ไม่แสดงวงเล็บ

## 2. ย้ายตารางการอนุมัติ

### 2.1 แท็บติดตามสถานะ — รวมเป็นตารางเดียว

รวม "รายการที่ต้องดำเนินการ" (CR-12 ข้อ 3.6) กับ "ประวัติการอนุมัติ" เป็น **ตารางเดียว 1 แถวต่อหน่วยขาย** (แสดงทุกหน่วยขาย ไม่ใช่เฉพาะที่มีประเด็น)

บรรทัดสรุปเหนือตาราง: `จัดสรรเป้าหมายประจำปี: {สถานะ} · {ผู้อนุมัติ} · {วันที่}` และ `Baseline: ยังไม่ล็อก` หรือ `ล็อกแล้ว {ฉบับที่} · {วันที่}`

| กลุ่มคอลัมน์ | คอลัมน์ |
|---|---|
| หน่วยขาย | Channel (แถบสี) · หน่วยขาย (ลิงก์) · ผู้รับผิดชอบ |
| ตัวเลข | ส่วนต่าง (ล้านบาท) |
| เป้าหมายรายเดือน | สถานะ · ผู้อนุมัติ · วันที่อนุมัติ |
| แผน SKU | สถานะ · ผู้อนุมัติ · วันที่อนุมัติ |
| | การดำเนินการถัดไป |

- ยังไม่อนุมัติ: ช่องผู้อนุมัติและวันที่แสดง `–` (สถานะอยู่ในคอลัมน์สถานะแล้ว ไม่ต้องซ้ำ)
- หัวตาราง 2 ชั้น (กลุ่มคอลัมน์ `เป้าหมายรายเดือน` และ `แผน SKU` ครอบคอลัมน์ย่อย)
- ตัวกรองเดิมคงไว้ และเพิ่มสวิตช์ `แสดงเฉพาะที่มีประเด็น` (ค่าเริ่มต้นปิด)
- การเรียงลำดับตามความรุนแรงแบบ CR-12 ข้อ 3.6 คงไว้ หน่วยที่ไม่มีประเด็นอยู่ท้ายตาราง
- กดที่สถานะแล้วเปิดประวัติ Workflow ของขั้นนั้นแบบ Popover (ผู้ส่ง · วันที่ส่ง · การส่งกลับแก้ไข · ผู้อนุมัติ)

### 2.2 แท็บรายงานสรุปแผน — ส่วนการอนุมัติแบบย่อ

- **ยังไม่ล็อก Baseline:** แสดงบรรทัดเดียวใต้หัวรายงาน `การอนุมัติ: อนุมัติครบแล้ว {x}/{y} หน่วยขาย` ตัดตารางการอนุมัติ 19 แถวเดิมออก
- **ล็อก Baseline แล้ว:** ตาราง `การอนุมัติ` แบบย่อ 1 แถวต่อหน่วยขาย: หน่วยขาย · เป้าหมายรายเดือน (ผู้อนุมัติ · วันที่) · แผน SKU (ผู้อนุมัติ · วันที่) และบรรทัด Top-down ด้านบน ตามด้วยช่องลงนาม (CR-12 ข้อ 3.7)

## 3. มุมมองรวมในหน้าจัดสรรเป้าหมายรายเดือน

### 3.1 ตัวเลือก

- ปุ่ม Channel เพิ่มตัวเลือกแรก **`ทั้งหมด`**
- Dropdown หน่วยขาย เพิ่มตัวเลือกบนสุด **`รวมทั้ง {Channel} ({n} หน่วย)`** คั่นด้วยเส้นจากรายการหน่วยขาย
- เลือก `ทั้งหมด` → Dropdown แสดงเฉพาะ `รวมทุก Channel`
- ปุ่ม `‹ ›` ไล่ได้ถึงตัวเลือกรวมด้วย
- เพิ่มใน `subChannelPicker` เป็นตัวเลือก `allowAggregate: true` (หน้าวางแผนราย SKU ไม่เปิดใช้)

### 3.2 การแสดงผลในมุมมองรวม

- **อ่านอย่างเดียว:** ซ่อนปุ่ม `แก้ไข` และ `ส่งอนุมัติ` แสดงข้อความแทน `มุมมองรวม · เลือกหน่วยขายเพื่อแก้ไข`
- แถบบริบท: `เป้าหมายทั้งปี` · `ยอดขายปี 2026` · `การเติบโต` ของผลรวม ไม่แสดงผู้รับผิดชอบและ GP
- **กราฟ:**
  - ค่าเริ่มต้น = แท่งซ้อนตามหน่วยขาย (สีโทนเดียวกับ Channel ไล่ความเข้มตามหน่วยขาย ในมุมมอง `รวมทุก Channel` ซ้อนตาม Channel ใช้สี Channel) + เส้นประยอดปีก่อนรวม
  - สวิตช์ `แท่งรวม | แยกตามหน่วยขาย` (มุมมองทุก Channel เป็น `แยกตาม Channel`)
  - Legend กดชื่อหน่วยขายแล้วไปมุมมองของหน่วยนั้น
  - แกน Y เริ่มที่ 0 ใช้ `niceScaleMax` (headroom 10%)
- **ตาราง:** แถว `ยอดขายปีก่อน` · `สัดส่วนรายเดือน (%)` (ของผลรวม) · `เป้าหมาย Net Sales` · `การเติบโต` และเพิ่มแถวย่อยต่อหน่วยขาย (พับได้ ค่าเริ่มต้นพับ) แสดงเป้าหมายรายเดือนของแต่ละหน่วย
- ไม่มีแถวคงเหลือรายเดือน (คงเหลือคิดต่อหน่วยขาย) แต่แสดงบรรทัดสรุป `หน่วยขายที่ยังจัดสรรไม่ครบ: {x} หน่วย` พร้อมลิงก์
- ส่งออก Excel/CSV ได้ (ผลรวม + แถวต่อหน่วยขาย)

### 3.3 คำนวณ

- ฟังก์ชัน `aggregatePhasing(unitIds, year)` ใน `calc.js` รวมเป้าหมายและยอดปีก่อนรายเดือน ไม่เก็บผลรวมลง store (คำนวณทุกครั้ง)

## 4. Test

1. แท็บเริ่มต้น = รายงานสรุปแผน ทั้งก่อนและหลังล็อก Baseline
2. ตารางติดตามสถานะมี 9 แถว (1 ต่อหน่วยขาย) และหน่วยที่ยังไม่อนุมัติแสดง `–` ในช่องผู้อนุมัติ
3. รายงานก่อนล็อก Baseline ไม่มีตารางการอนุมัติ มีบรรทัด `อนุมัติครบแล้ว 0/9 หน่วยขาย`
4. `aggregatePhasing([7-Eleven, Watsons, EVEANDBOY])` เดือน ม.ค. = ผลรวมเป้าหมาย ม.ค. ของ 3 หน่วย และทั้งปี = 54,000,000
5. มุมมองรวมไม่มีปุ่มแก้ไข และเลือกหน่วยขายจาก Legend แล้วกลับเป็นมุมมองแก้ไขได้
