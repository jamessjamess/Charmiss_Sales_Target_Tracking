# CR-12: ปรับหน้ารายงานสรุปแผน (ขั้นที่ 4)

> สั่ง Claude Code: "อ่าน docs/change-requests/CR-12_summary-report.md, CLAUDE.md และหัวข้อ 8, 9, 12 ใน docs/SPEC.md แล้วสรุปไฟล์ที่จะแก้ก่อนเริ่ม"
> ทำหลังจาก CR-11 เสร็จแล้ว

## 1. เป้าหมาย

1. ทำให้กราฟอ่านง่ายและไม่หลอกตา
2. ทำให้ตารางกระชับ และพิมพ์ออกมาไม่ซ้อนกัน
3. แยกเนื้อหาที่ใช้ติดตามงานออกจากรายงาน เพื่อให้รายงานใช้เป็นประกาศและหลักฐานข้อตกลงได้

## 2. ขอบเขต

## 3. รายละเอียด

### 3.1 แบ่งขั้นที่ 4 เป็น 2 แท็บ

> **แทนที่โดย CR-13 ข้อ 1** (2026-09-25): ลำดับแท็บ `รายงานสรุปแผน` | `ติดตามสถานะ (n)` และเปิดแท็บรายงานเป็นค่าเริ่มต้นเสมอ

ขั้นที่ 4 ยังเป็นหน้าเดียวในเมนู (Sales Planning ยังมี 4 ขั้น) แต่มีแท็บใต้หัวข้อ:

| แท็บ | เนื้อหา | พิมพ์ / ส่งออก |
|---|---|---|
| **ติดตามสถานะ** (ค่าเริ่มต้นเมื่อยังไม่ล็อก Baseline) | บรรทัดสรุปสถานะทั้งปี · ตารางรายการที่ต้องดำเนินการ (ข้อ 3.6) · ปุ่ม `ล็อก Baseline {ปี}` | ไม่ได้ |
| **รายงานสรุปแผน** (ค่าเริ่มต้นเมื่อล็อก Baseline แล้ว) | KPI · กราฟ · ตาราง Channel/หน่วยขาย · สัดส่วนตามกลุ่มสินค้า · เป้าหมายรายผู้รับผิดชอบ · ส่วนการอนุมัติ (ข้อ 3.7) | ได้ (ปุ่ม `พิมพ์ / บันทึก PDF` อยู่ในแท็บนี้เท่านั้น) |

- จำแท็บล่าสุดที่ `ui.summaryTab`
- ชื่อแท็บ ป้าย และข้อความทั้งหมดอยู่ใน `content.js`
- ไอคอนสถานะในเมนูข้างของขั้นที่ 4 แสดงจำนวนรายการที่ต้องดำเนินการ (เช่น `9`)

### 3.2 กราฟเป้าหมายเทียบแผน รายเดือน

**แยกชุดข้อมูลให้ต่างกันชัดเจน** (สี + ความหนา + รูปแบบ):

| ชุดข้อมูล | รูปแบบ |
|---|---|
| เป้าหมาย (Top-down Phasing) | แท่ง สีหลักแบบอ่อน (ความเข้มประมาณ 35–45%) |
| แผน Bottom-up | เส้นทึบหนา 3px สีเข้ม (Token ใหม่ `--chart-plan`) จุดทึบทุกเดือน |
| ยอดขายปี 2026 | เส้นประบาง 1.5px สีเทาอ่อน (`--chart-lastyear`) ไม่มีจุด |

- ป้ายชื่อท้ายเส้นที่เดือน ธ.ค. เช่น `แผน 12.70` และ `ปี 2026 11.90` (ถ้าป้ายชนกันให้เลื่อนขึ้น/ลงไม่ให้ทับ)
- Legend ใช้รูปสัญลักษณ์ตรงกับที่วาดจริง (แท่ง / เส้นทึบมีจุด / เส้นประ)
- Tooltip เมื่อ Hover เดือน: เป้าหมาย · แผน · ส่วนต่าง · ยอดปีก่อน

**แกน Y:**
- เริ่มที่ 0 เสมอ
- ค่าสูงสุด = ค่ามากที่สุดของทั้ง 3 ชุด × 1.10 แล้วปัดขึ้นเป็นเลขกลม (ใช้ `SP.core.charts.niceScaleMax` ตัวเดียวกับตาราง Top-down เพิ่มตัวเลือก headroom)
- เส้นแบ่งแกน 4–6 เส้น ขั้นละ 1 / 2 / 2.5 / 5 / 10 … ล้าน (เลือกให้ได้จำนวนเส้นในช่วงนี้)
- ตัวอย่าง: ค่ามากที่สุด 12.9 ล้าน → แกน 0–15 ขั้นละ 2.5 หรือ 5

### 3.3 กราฟที่มาของการเติบโต (Waterfall)

**แกนเริ่มที่เลขกลม ไม่เริ่มที่ค่าครึ่งๆ กลางๆ:**

```
ค่าต่ำสุด = ค่าที่น้อยที่สุดของ { ยอดปีก่อน, Total Target, ยอดสะสมทุกขั้นของ Waterfall }
ขั้นของแกนเริ่ม:
  ค่าต่ำสุด ≥ 200 ล้าน  → ขั้นละ 100 ล้าน
  ค่าต่ำสุด ≥ 50 ล้าน   → ขั้นละ 50 ล้าน
  น้อยกว่า 50 ล้าน      → เริ่มที่ 0
แกนเริ่ม = ปัดลง(ค่าต่ำสุด ÷ ขั้น) × ขั้น
```

ตัวอย่าง: 113.2 ล้าน → 100 ล้าน · 245 ล้าน → 200 ล้าน · 40 ล้าน → 0

- แท่ง `ยอดขายปี 2026` และแท่ง `Total Target 2027` **เริ่มที่แกนเริ่มจุดเดียวกัน** (ขอบซ้ายตรงกัน)
- แท่งของแต่ละ Channel ลอยต่อจากยอดสะสมของขั้นก่อนหน้า (เพิ่ม = เขียว ลด = แดง) ตามสเกลเดียวกับแท่งยอดรวม
- ค่าสูงสุดของแกน = ค่ามากที่สุดของยอดสะสม ปัดขึ้นเป็นเลขกลม เส้นแบ่งแกน 4–6 เส้นพร้อมตัวเลขใต้แกน
- ถ้าแกนไม่เริ่มที่ 0 ให้แสดงสัญลักษณ์ตัดแกน (เส้นซิกแซกเล็กที่ต้นแกน) และข้อความใต้กราฟ `แกนเริ่มที่ 100 ล้านบาท` (ตัวเลขจากการคำนวณ)
- ตัวเลขท้ายแท่ง: ยอดรวมแสดงเป็นล้านบาท ส่วนเพิ่มแสดงเครื่องหมาย + / −
- ฟังก์ชัน `SP.core.charts.axisStart(values)` ใน `core/charts.js` และค่าขั้น (50 / 100 ล้าน, เกณฑ์ 50 / 200 ล้าน) อยู่ใน `data/settings.js`
- แท่งสัดส่วน Channel ปี 2026 เทียบปี 2027 คงไว้ใต้ Waterfall เหมือนเดิม

### 3.4 สัดส่วนความกว้างของกราฟ

- กราฟรายเดือน : การ์ดที่มาของการเติบโต = **60 : 40** (จากเดิมที่กราฟรายเดือนกว้างกว่ามาก)
- ความสูงของสองการ์ดเท่ากัน และอยู่หน้าเดียวกันเมื่อพิมพ์ A4 แนวนอน
- จอแคบกว่า 1280px ให้เรียงลงเป็นคอลัมน์เดียว

### 3.5 ตารางเป้าหมายและแผนราย Channel และหน่วยขาย

- เพิ่มคอลัมน์ **`% ของ Total`** (สัดส่วนเป้าหมายเทียบ Total Target) ต่อจากคอลัมน์เป้าหมาย ไม่เพิ่ม `% ใน Channel`
- **ย้ายสถานะ Top-down ออกจากตาราง** ไปแสดงที่หัวรายงาน (ข้อ 3.7) ตัดคอลัมน์ที่ Merge ทั้งคอลัมน์ออก
- **รวมสถานะ Phasing และ SKU เป็นคอลัมน์เดียว** `สถานะอนุมัติ` แสดงไอคอน 2 ตัวเรียงกัน (Phasing · SKU) ตามสถานะ: ฉบับร่าง `○` · รออนุมัติ `◐` · อนุมัติแล้ว `●` · ส่งกลับแก้ไข `↩` · ต้องตรวจสอบใหม่ `!` พร้อม Tooltip ข้อความเต็ม และคำอธิบายสัญลักษณ์บรรทัดเดียวใต้ตาราง แถว Channel แสดง `อนุมัติแล้ว 0/3`
- คอลัมน์ผู้รับผิดชอบกว้างพอให้ชื่อ–นามสกุลอยู่บรรทัดเดียว
- ลำดับคอลัมน์: `Channel / หน่วยขาย · ยอดขายปี 2026 · เป้าหมาย · % ของ Total · เป้าหมายเทียบปีก่อน · แผน Bottom-up · ส่วนต่าง · สถานะอนุมัติ · ผู้รับผิดชอบ`
- **ตอนพิมพ์:** ซ่อนไอคอน `ⓘ` · กำหนดความกว้างคอลัมน์คงที่ (`table-layout: fixed`) · หัวคอลัมน์ห้ามซ้อนกัน (ปัจจุบัน PDF แสดง "ยอดขายปี 2026ⓘเป้าหมาย" และ "แผน Bottom-ส่วนต่าง") · หัวตารางแสดงซ้ำทุกหน้า (`thead { display: table-header-group }`) · ห้ามตัดแถวกลางหน้า (`tr { break-inside: avoid }`)

### 3.6 รายการที่ต้องดำเนินการ (แท็บติดตามสถานะ)

**บรรทัดสรุปทั้งปี** เหนือตาราง (เรื่องที่ไม่ใช่ของหน่วยใดหน่วยหนึ่ง): เช่น `จัดสรรเป้าหมายประจำปียังไม่ได้รับอนุมัติ (ฉบับร่าง)` · `ยังไม่ล็อก Baseline`

**ตาราง** 1 แถวต่อหน่วยขายที่มีประเด็น:

| คอลัมน์ | รายละเอียด |
|---|---|
| Channel | แถบสีซ้ายตาม Channel |
| หน่วยขาย | ลิงก์ไปหน้าวางแผนของหน่วยนั้น |
| ผู้รับผิดชอบ | ชื่อ หรือ `ยังไม่มีผู้รับผิดชอบ` (สีแดง) |
| ส่วนต่าง (ล้านบาท) | `ขาด x` / `เกิน x` / `จัดสรรครบ` สีตามมาตรฐาน |
| เป้าหมายรายเดือน | สถานะ Workflow แบบข้อความสั้น (`ยังไม่ส่ง` / `รออนุมัติ` / `อนุมัติแล้ว` / `ส่งกลับแก้ไข` / `ต้องตรวจสอบใหม่`) |
| แผน SKU | แบบเดียวกัน |
| การดำเนินการถัดไป | ข้อความสั้นไม่เกิน 4 คำ เช่น `ปิดส่วนต่าง`, `ส่งอนุมัติ`, `กำหนดผู้รับผิดชอบ`, `รออนุมัติจาก Director` |

- เรียงตามความรุนแรง: ยังไม่มีผู้รับผิดชอบ → ส่งกลับแก้ไข / ต้องตรวจสอบใหม่ → ส่วนต่างมากไปน้อย → ยังไม่ส่ง
- ตัวกรองเล็กเหนือตาราง: Channel · ผู้รับผิดชอบ · `เฉพาะที่มีส่วนต่าง`
- หน่วยขายที่ไม่มีประเด็นไม่แสดง ถ้าไม่มีประเด็นเลยแสดง `ไม่มีรายการที่ต้องดำเนินการ`
- ตัดประโยคยาวแบบเดิมทั้งหมด

### 3.7 ทำให้รายงานใช้เป็นหลักฐานได้ (แท็บรายงานสรุปแผน)

> **ส่วน "การอนุมัติ" แทนที่โดย CR-13 ข้อ 2** (2026-09-25): ประวัติการอนุมัติย้ายไปแท็บติดตามสถานะ · รายงานก่อนล็อกเหลือบรรทัดเดียว ·
> หลังล็อกเป็นตารางย่อ 1 แถวต่อหน่วยขาย + ช่องลงนาม (หัวรายงาน เลขฉบับ ลายน้ำ Snapshot ยังใช้ตามข้อนี้)

**หัวรายงาน:**

```
รายงานสรุปแผน 2027                                          ฉบับที่ 2027-BL-01
สถานะ: อนุมัติแล้ว · ล็อก Baseline 15 พ.ย. 2026 14:30 โดย {Sales Director}
จัดสรรเป้าหมายประจำปี: อนุมัติแล้ว 2 พ.ย. 2026 โดย {Management}
พิมพ์เมื่อ {วันเวลา}
```

- **ยังไม่ล็อก Baseline:** เลขฉบับ `2027-DRAFT` · สถานะ `ฉบับร่าง · ยังไม่ได้รับอนุมัติ` · **ลายน้ำเฉียงจาง "ฉบับร่าง · ยังไม่ได้รับอนุมัติ" ทุกหน้า** ทั้งบนจอและตอนพิมพ์
- **ล็อก Baseline แล้ว:** ตัวเลขทั้งหมดในรายงานมาจาก Snapshot ของ Baseline (ไม่ใช่ข้อมูลที่ยังแก้ได้) และมีหมายเหตุท้ายหัวรายงาน `ตัวเลขในรายงานนี้มาจาก Baseline ที่ล็อกไว้`
- **เลขฉบับ:** `{ปี}-BL-{ลำดับ 2 หลัก}` เพิ่มขึ้นทุกครั้งที่ล็อก Baseline ใหม่ (หลังจากเปิดให้แก้ไขแล้วอนุมัติใหม่) เก็บประวัติเลขฉบับไว้ใน `plan.<year>.baselineVersions`
- **ส่วน "การอนุมัติ" ท้ายรายงาน** (ตาราง): ขั้นตอน · หน่วยขาย · ผู้ส่ง · วันที่ส่ง · ผู้อนุมัติ · วันที่อนุมัติ ครอบคลุม Top-down และ Phasing/SKU ของทุกหน่วยขาย ดึงจากประวัติ Workflow
- ท้ายหน้าสุดท้าย: ช่องลงนามว่างสำหรับพิมพ์ 2 ช่อง `Sales Director` และ `Management` (ชื่อ · ลายมือชื่อ · วันที่)

## 4. Test

1. `axisStart([113.2M, 120M, 115.5M, 116.6M])` → 100M
2. `axisStart([245M, 260M])` → 200M
3. `axisStart([40M, 45M])` → 0
4. `axisStart([100M, 120M])` → 100M (ค่าที่เป็นเลขกลมพอดีไม่ถูกปัดลงอีกขั้น)
5. `niceScaleMax([12.9M, 12.7M, 11.9M], { headroom: 0.10 })` → 15M
6. Waterfall: แท่งยอดปี 2026 และ Total Target มีจุดเริ่มต้นเท่ากัน (= แกนเริ่ม)
7. เลขฉบับ: ล็อกครั้งแรก → `2027-BL-01` · เปิดให้แก้ไขแล้วล็อกใหม่ → `2027-BL-02` · ยังไม่ล็อก → `2027-DRAFT`
8. รายการที่ต้องดำเนินการ: หน่วยที่ไม่มีผู้รับผิดชอบอยู่แถวแรก หน่วยที่จัดสรรครบและอนุมัติครบไม่แสดง
9. `% ของ Total` ของ 7-Eleven: 22,140,000 ÷ 120,000,000 → 18.45%

## 5. สิ่งที่ห้ามทำ

- ห้ามเริ่มแกน Waterfall ที่ค่าที่ไม่ใช่เลขกลมตามกฎข้อ 3.3
- ห้ามให้แท่งยอดปี 2026 และ Total Target เริ่มคนละจุด
- ห้ามใช้สีหรือรูปแบบเส้นเดียวกันระหว่างแผน Bottom-up และยอดขายปี 2026
- ห้ามพิมพ์หรือส่งออกแท็บติดตามสถานะ
- ห้ามพิมพ์รายงานที่ยังไม่ล็อก Baseline โดยไม่มีลายน้ำฉบับร่าง
- ห้ามให้รายงานที่ล็อกแล้วอ่านตัวเลขจากข้อมูลที่ยังแก้ได้

## 6. ตรวจก่อนส่งงาน

1. Test ทั้งหมดผ่าน
2. กราฟรายเดือน: แกนสูงสุดเหมาะกับข้อมูล (ไม่เหลือพื้นที่ว่างด้านบนเกินราว 15%) และแยกเส้นแผนกับยอดปีก่อนได้ทันทีแม้พิมพ์ขาวดำ
3. Waterfall: แกนเริ่ม 100 ล้าน มีสัญลักษณ์ตัดแกน แท่งรวมทั้งสองเริ่มจุดเดียวกัน และแท่งราย Channel มองเห็นชัดขึ้น
4. สองการ์ดกราฟกว้าง 60 : 40 และสูงเท่ากัน
5. ตารางมี `% ของ Total` ไม่มีคอลัมน์ Top-down และพิมพ์แล้วหัวคอลัมน์ไม่ซ้อน ชื่อไม่ตัดบรรทัด หัวตารางซ้ำทุกหน้า
6. แท็บติดตามสถานะแสดงรายการเป็นตาราง เรียงตามความรุนแรง และพิมพ์ไม่ได้
