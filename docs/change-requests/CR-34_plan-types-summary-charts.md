## 1. ประเภทสินค้าในแผน

### 1.1 นิยาม (ต่อ SKU × หน่วยขาย)

| ประเภท | key | เงื่อนไข |
|---|---|---|
| สินค้าเดิม | `existing` | Status `Active` และมียอดขายในหน่วยขายนี้ในข้อมูลย้อนหลังที่มี (2024 · 2025 · 2026 ถึงเดือนปิดล่าสุด) |
| Listing ใหม่ | `newListing` | Status `Active` แต่ไม่เคยมียอดขายในหน่วยขายนี้ |
| NPD ยืนยันแล้ว | `npdConfirmed` | Status `NPD` |
| ขอ NPD | `npdRequest` | Status `Planned` |
| Clearance | `clearance` | Status `Clearance` |

- ใส่ใน `core/calc.js` ชื่อ `SP.calc.planTypeOf(sku, salesUnitId)`
- ป้ายและสีอยู่ใน `content.js` ที่เดียว ใช้ร่วมกันทั้ง SKU Planning และ Plan Summary
- ถ้า Code ปัจจุบันใช้ Status `Planned` ในความหมายอื่น ให้หยุดและแจ้งก่อนทำต่อ
- ในกราฟ Plan Summary `newListing` นับรวมกับ `existing` ภายใต้ชื่อ `สินค้าเดิม` เพื่อให้เหลือ 3 ส่วนหลัก
- `newListing` ยังแยกให้เห็นได้ใน Tooltip และใน SKU Planning

### 1.2 สีและป้าย (ใช้เหมือนกันทุกจุด)

| ประเภท | สี | ป้ายบนแถว SKU |
|---|---|---|
| สินค้าเดิม | สีหลักของระบบ (ม่วงแดงเข้ม) | ไม่มีป้าย |
| Listing ใหม่ | สีหลัก | `Listing ใหม่` (ขอบสีหลัก พื้นขาว) |
| NPD ยืนยันแล้ว | ม่วง (สีเดียวกับ NPD เดิม) | `NPD` (พื้นม่วงอ่อน) |
| ขอ NPD | ม่วงอ่อนลายเส้นทแยง | `ขอ NPD` (ขอบประม่วง พื้นขาว) |
| Clearance | เทา | `Clearance` (พื้นเทาอ่อน) |

## 2. SKU Planning

### 2.1 จัดกลุ่ม

- ตัวเลือกจัดกลุ่มเป็น `Series | ประเภท | ไม่จัดกลุ่ม` (เปลี่ยน `Status` เป็น `ประเภท`)
- ลำดับกลุ่มเมื่อจัดตามประเภท: `สินค้าเดิม` → `Listing ใหม่` → `NPD ยืนยันแล้ว` → `ขอ NPD` → `Clearance`
- แสดงเฉพาะกลุ่มที่มีรายการ
- หัวกลุ่มแสดง `<ชื่อประเภท> · N รายการ` พร้อมยอดรวมรายเดือนตามเดิม
- กลุ่ม `สินค้าใหม่ (NPD) ปี 2027` เดิมถูกแทนด้วยกลุ่ม `NPD ยืนยันแล้ว` และ `ขอ NPD`
- เมื่อจัดกลุ่มตาม Series แต่ละแถวยังมีป้ายประเภทตามข้อ 1.2

### 2.2 แถวสินค้า

- บรรทัดใต้ชื่อเหลือ `รหัส · Series` เท่านั้น **ตัดช่องเลือก `เริ่มขาย` ออก**
- ชื่อยาวแสดงได้ 2 บรรทัดแล้วตัดด้วย `…` · ป้ายประเภทอยู่ท้ายบรรทัดแรกของชื่อ
- เมนู `…` คงเดิม และเพิ่มคำสั่ง `นำออกจากแผน` สำหรับ `Listing ใหม่` · `NPD ยืนยันแล้ว` · `ขอ NPD` ที่เพิ่มจากหน้านี้
  - ลบค่ารายเดือนและ Listing ที่สร้างจาก SKU Planning ของหน่วยขายนี้
  - ถ้าเป็น `ขอ NPD` ที่ไม่มีหน่วยขายอื่นใช้ ให้ถามต่อว่าจะยกเลิกคำขอ NPD ด้วยหรือไม่

### 2.3 คอลัมน์ช่วงเวลาขาย (แก้เดือนเริ่มขาย)

**โหมดดู**
- `สินค้าเดิม` / `Clearance`: แสดงช่วงเดิม เช่น `ม.ค. 23 – มี.ค. 26`
- สินค้าใหม่ทั้ง 3 ประเภท: แสดง `เริ่ม เม.ย. 27`

**โหมดแก้ไข** (เฉพาะ `Listing ใหม่` · `NPD ยืนยันแล้ว` · `ขอ NPD`)
- ช่องเป็นตัวเลือกเดือน `เริ่ม [เม.ย. 27 ▾]` ในคอลัมน์เดิม
- ช่วงที่เลือกได้คือเดือนแรกของปีแผนถึง `PLAN_HORIZON_END`
- **`NPD ยืนยันแล้ว`:** เลือกก่อนเดือนเปิดตัวในแผน NPD ไม่ได้ ตัวเลือกที่ก่อนหน้านั้นเป็นสีเทาและมี Tooltip `เปิดตัวตามแผน NPD <เดือน>`
- **เลื่อนเดือนเริ่มให้ช้าลง:** ถ้าเดือนก่อนหน้าเดือนใหม่มีจำนวนแล้ว ให้ถามยืนยัน `ค่าใน <ช่วงเดือน> จะถูกล้างเป็น 0`
- เดือนก่อนเดือนเริ่มล็อกเป็น 0 และสีเทาตามกติกา Listing เดิม
- นับเป็น 1 รายการในแถบ `มีรายการที่ยังไม่บันทึก`
- `สินค้าเดิม` และ `Clearance` แก้ไม่ได้ในคอลัมน์นี้

**ข้อมูลที่เขียน**
- ค่าที่แก้คือเดือนเริ่มของ Listing ของ SKU นี้ในหน่วยขายนี้ (โครง Listing จาก CR-30)
- Sales แก้ Listing ผ่านช่องทางนี้ได้เฉพาะ Listing ที่สร้างจาก SKU Planning (`source: 'skuPlanning'`) เท่านั้น
- เดือนเปิดตัวของคำขอ NPD (ระดับสินค้า) = เดือนเริ่มที่เร็วที่สุดของ Listing ทุกหน่วยขายของคำขอนั้น คำนวณอัตโนมัติ
- คอลัมน์ `อายุ` ของสินค้าใหม่ยังแสดง `ยังไม่เริ่มขาย` ตาม CR-33

### 2.4 ปุ่ม `+ เพิ่มสินค้าในแผน` และ Dialog

**ตำแหน่งปุ่ม** (โหมดแก้ไข)
- แถวคำสั่งข้าง `ปรับทั้งหน่วยขาย ±%` · `ปรับให้ครบตามเป้าหมาย`
- ในแถวคงเหลือท้ายตาราง แทน `+ สร้าง NPD`

**ปุ่มที่ตัดออก**
- `+ เพิ่ม SKU` ที่หัวคอลัมน์ SKU
- `+ เพิ่มสินค้าใหม่`
- `+ สร้าง NPD` ทุกจุด

**Dialog** `เพิ่มสินค้าในแผน · <ชื่อหน่วยขาย>` มีตัวเลือกแบบแท็บ 3 แบบ

| แท็บ | รายการที่แสดง | สิ่งที่เกิดเมื่อเพิ่ม |
|---|---|---|
| **สินค้าเดิมที่ยังไม่เคยขายในหน่วยขายนี้** | SKU Status `Active` ที่ยังไม่อยู่ในแผนของหน่วยขายนี้ ค้นหาได้ กรองตาม Series ได้ เลือกได้หลายรายการ · แสดงยอด L12M รวมทุกหน่วยขายเพื่อช่วยตัดสินใจ | เพิ่มแถวประเภท `Listing ใหม่` · สร้าง Listing ของหน่วยขายนี้สถานะ `วางขาย` ตั้งแต่เดือนที่เลือก (ค่าเริ่มต้น = เดือนแรกของปีแผน) `source: 'skuPlanning'` |
| **NPD ที่ยืนยันแล้ว** | สินค้า Status `NPD` ที่ยังไม่อยู่ในแผนของหน่วยขายนี้ พร้อมเดือนเปิดตัวตามแผน NPD เลือกได้หลายรายการ | เพิ่มแถว `NPD ยืนยันแล้ว` · เดือนเริ่มค่าเริ่มต้น = เดือนเปิดตัวตามแผน NPD · สร้าง Listing เช่นเดียวกัน |
| **ขอ NPD เพิ่ม** | ฟอร์มสร้าง NPD เดิม (ชื่อชั่วคราว · Series · หมวด · ราคา · เดือนเริ่มขาย) + ช่อง `เหตุผล / แนวคิดสินค้า` | สร้างสินค้า Status `Planned` · `source: 'sales'` · ผู้ขอ = ผู้ใช้ปัจจุบัน · เพิ่มแถว `ขอ NPD` · สร้าง Listing เช่นเดียวกัน |

- แต่ละแท็บมีคำอธิบายหนึ่งบรรทัดใน `content.js`
  - ขอ NPD: `ทีม Product จะเห็นคำขอนี้ในหน้าแผน NPD และเปลี่ยนเป็น NPD เมื่อยืนยัน`
- ถ้าเลือกหลายรายการในแท็บ 1 หรือ 2 ให้ใช้เดือนเริ่มเดียวกันทุกรายการ และแก้รายแถวได้ภายหลังในคอลัมน์ช่วงเวลาขาย
- จำนวนเริ่มต้นเป็น 0 ทุกเดือน
- **ข้อความแจ้งเดิม** `มีสินค้าใหม่ที่ Listing แล้วแต่ยังไม่อยู่ในแผน N รายการ` คงไว้ แต่ข้อความท้ายเปลี่ยนเป็นลิงก์ `เพิ่มสินค้าในแผน` ที่เปิด Dialog ในแท็บที่ตรงกับรายการนั้น
- **สิทธิ์:** ใช้สิทธิ์ของหน้า SKU Planning สำหรับหน่วยขายนั้น (Sales Manager/Officer เฉพาะ Channel ในทีม)
  - ตรวจสิทธิ์ที่ฟังก์ชัน ไม่ใช่แค่ซ่อนปุ่ม

### 2.5 หน้าแผน NPD (Product Master)

- เพิ่มคอลัมน์ `แหล่งที่มา`
  - `ทีม Product` หรือ `Sales · <ชื่อผู้ขอ>`
  - Tooltip แสดงเหตุผลที่ Sales ระบุ
- เพิ่มคอลัมน์ `ใช้ในแผน` แสดงจำนวนหน่วยขายที่มีสินค้านี้ในแผน
- ตัวกรองสถานะมี `Planned` อยู่แล้ว ให้เพิ่ม Chip ลัด `คำขอจาก Sales (N)`
- ทีม Product ยืนยันด้วยการเปลี่ยน Status `Planned` → `NPD` ตามการแก้ไขปกติของหน้า (ไม่มีขั้นอนุมัติ)
  - เมื่อเปลี่ยนแล้ว แถวใน SKU Planning เปลี่ยนเป็นประเภท `NPD ยืนยันแล้ว` อัตโนมัติ
  - ห้ามเปิดใช้ Flag `npdApproval`

### 2.6 Seed

เพิ่มข้อมูลให้ Demo เห็นครบ 4 ประเภท

## 3. Plan Summary: กราฟเป้าหมายเทียบแผนรายเดือน

อยู่ที่แท็บรายงานของ Plan Summary ตำแหน่งเดิม ให้ตรวจตำแหน่งจริงใน Repo · SVG วาดเอง

### 3.2 รายละเอียด

**แท่งซ้อน (แผน Bottom-up)**
- ลำดับจากล่างขึ้นบน: `สินค้าเดิม` → `NPD ยืนยันแล้ว` → `ขอ NPD`
- ถ้ามีแผน `Clearance` ให้เพิ่มส่วนสีเทาบนสุด และแสดงใน Legend เฉพาะตอนนั้น
- ส่วนที่มีค่า 0 ไม่ต้องวาด

**เป้าหมาย Top-down**
- ขีดแนวนอนสีเข้ม หนา 3px กว้างกว่าแท่งเล็กน้อยทั้งสองข้าง (ประมาณ 8px) วางที่ค่าเป้าหมายของเดือนนั้น
- ไม่ลากเส้นเชื่อมระหว่างเดือน
- ชื่อใน Legend: `เป้าหมาย Top-down`

**ยอดขายอ้างอิง**
- เส้นประสีเทาบาง เชื่อมจุดกึ่งกลางแต่ละเดือน
- ใช้ยอดอ้างอิงรายเดือนตามกติกาเดิม (ม.ค.–ส.ค. จาก 2026 · ก.ย.–ธ.ค. จาก 2025)
- คลิกที่ Legend เพื่อซ่อน/แสดงได้ ค่าเริ่มต้นแสดง

**แกน Y**
- เริ่มที่ 0 ตามมาตรฐานแท่งเทียบ
- ค่าสูงสุดปัดขึ้นเป็นเลขกลมจากค่าที่มากที่สุดระหว่างแท่ง เป้าหมาย และยอดอ้างอิง

**แถวส่วนต่างใต้แกน X**
- ค่า = แผน − เป้าหมาย (ล้านบาท ทศนิยม 1 ตำแหน่ง)
- สีตามมาตรฐานแถวคงเหลือ:
  - ครบ (|ส่วนต่าง| < 0.05): เขียว แสดง `ครบ`
  - ขาด: แดง
  - เกิน: เหลือง
  - ไม่มีเป้าหมาย: เทา

**หัวกราฟขวา (สรุปทั้งปี)**
- `ทั้งปี  เป้าหมาย X · แผน Y · <ขาด/เกิน/ครบ> Z (z%)` สีตามสถานะ
- ตัดข้อความ `อ้างอิง 10.35 / แผน 10.32` ที่ขวาสุดของกราฟเดิมออก

**Tooltip ต่อเดือน**
- เป้าหมาย Top-down
- แผนรวม
- แยก: สินค้าเดิม (ในวงเล็บแสดง Listing ใหม่ x) · NPD ยืนยันแล้ว · ขอ NPD · Clearance ถ้ามี
- ส่วนต่าง
- ยอดขายอ้างอิง

**ข้อมูล**
- ใช้ตัวชี้วัดและขอบเขตตัวกรองเดียวกับกราฟเดิม (Net Sales ล้านบาท ตาม Channel / หน่วยขายที่เลือก)
- ใช้ฟังก์ชันใหม่ `SP.calc.planByTypeMonthly(scope)` คืน `{ month, target, reference, existing, newListing, npdConfirmed, npdRequest, clearance }`
- ลายน้ำ `ฉบับร่าง` คงเดิม

## 4. Plan Summary: สัดส่วนแผนตามกลุ่มสินค้า

การ์ดเดิมแบ่งเป็น 2 คอลัมน์ 50 : 50 · Legend ประเภทร่วมกันอยู่ที่หัวการ์ด

```
สัดส่วนแผนตามกลุ่มสินค้า (ล้านบาท)          ■ สินค้าเดิม  ■ NPD ยืนยันแล้ว  ▨ ขอ NPD
┌ ตามประเภทแผน ─────────────────┐ ┌ ตามกลุ่มสินค้า            [Series | Category] ┐
│ สินค้าเดิม       ████████████ 108.2 · 97.5% │ │ Sanrio Blooming Heart ███████▨ 34.55 · 31.0% │
│   รวม Listing ใหม่ 1.2 · 2 SKU               │ │ Charming Lab          ██████   30.77 · 27.6% │
│ NPD ยืนยันแล้ว   █            2.1 · 1.9%   │ │ Charming Color        ████▒    23.00 · 20.7% │
│ ขอ NPD          ▨            0.7 · 0.6%   │ │ ...                                          │
│                                           │ │                                              │
│ สินค้าใหม่รวม 2.8 · 2.5% ของแผน              │ │                                              │
└───────────────────────────────────────────┘ └──────────────────────────────────────────────┘
```

### 4.1 ซ้าย: ตามประเภทแผน

**แถวแท่ง**
- 1 แถวต่อประเภท: `สินค้าเดิม` · `NPD ยืนยันแล้ว` · `ขอ NPD`
- `Clearance` แสดงเป็นแถวที่ 4 เฉพาะเมื่อมีค่า พร้อมข้อความแดงเล็ก `Clearance ไม่ควรอยู่ในแผน`
- แท่งสเกลจริงเริ่มที่ 0 ใช้ค่าสูงสุดเดียวกันทุกแถว

**ค่าท้ายแท่ง**
- `มูลค่า · %` เหมือนรูปแบบเดิมด้านขวา
- ใต้ชื่อประเภทมีบรรทัดเล็กสีเทาแสดงจำนวน SKU เช่น `42 SKU`
- `สินค้าเดิม` บรรทัดเล็กแสดง `รวม Listing ใหม่ x · N SKU`

**การทำให้ค่าเล็กยังอ่านได้**
- แท่งที่มีค่ามากกว่า 0 แต่กว้างน้อยกว่า 4px ให้วาดกว้าง 4px
- ตัวเลขท้ายแท่งแสดงเสมอ

**บรรทัดสรุปท้าย**
- `สินค้าใหม่รวม X · x% ของแผน` (NPD ยืนยันแล้ว + ขอ NPD + Listing ใหม่)
- ถ้าสินค้าเดิมอย่างเดียวไม่พอเป้าหมาย ให้แสดงเพิ่ม `ช่องว่างที่สินค้าใหม่ต้องปิด Y` เมื่อ Y > 0
  - Y = เป้าหมาย − สินค้าเดิม (ไม่รวม Listing ใหม่)

### 4.2 ขวา: ตามกลุ่มสินค้า

- คงตัวสลับ `Series | Category` และลำดับมากไปน้อยเดิม
- แท่งแต่ละแถวซ้อนตามประเภท (สีเดียวกับซ้าย) เพื่อให้เห็นว่ากลุ่มสินค้าใดพึ่งสินค้าใหม่
- สเกลเริ่ม 0 ค่าสูงสุดเดียวกันทุกแถว
- ค่าท้ายแท่ง `มูลค่า · %` ของแผนรวม
- Tooltip แสดงค่าแยกประเภท
- `(ไม่ระบุ Series)` คงไว้ท้ายสุด
- ถ้ารายการเกินความสูงของการ์ด ให้เลื่อนภายในคอลัมน์ขวา ความสูงการ์ดไม่เกินเดิม

### 4.3 ตัดออก

- แท่งเดี่ยวยาว `ตาม Status` และ Legend `Active · NPD · Clearance · 0%`
