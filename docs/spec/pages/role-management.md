# Role Management — Permissions · Users (`modules/role-management`)

กลุ่ม Role Management ในเมนูข้าง (CR-25 · ต่อจาก Account Master) · fit · ผู้แก้ไขตั้งต้น: ผู้ดูแลระบบ (บทบาทอื่นไม่เห็น) ·
กฎสิทธิ์ ค่าตั้งต้น เมนูตามบทบาท และหน้าเริ่มต้นดู `permissions.md` · CR-31 เหลือ 2 หน้า (แทน CR-21 ข้อ 4 · CR-25 ข้อ 1 และข้อ 4)

| หน้า | id | ไฟล์ | ไอคอน | เนื้อหา |
|---|---|---|---|---|
| Permissions | `roleManagement` | `index.html` | K | สิทธิ์ตามหน้า + จัดการบทบาทที่หัวคอลัมน์ |
| Users | `roleUsers` | `users/index.html` | U | ผู้ใช้ × สิทธิ์ที่มีผลจริงของ Module ที่เลือก + Drawer |
| (Roles) | `roleRoles` | `roles/index.html` | R | `visible: false` · เปิดลิงก์เดิม = พาไปหน้า Permissions (`location.replace`) |

- ทุกหน้าโหลด `role-management.js` ไฟล์เดียว (เนื้อหาตาม id ของหน้า) และใช้สิทธิ์เดียว `roleManagement` (registry `perm`) — แถวในเมทริกซ์ `Permissions / Users`
- ข้อความที่ใช้ร่วมอยู่ที่ `content.pages.roleManagement` (`matrix` · `usersTab`) · ชื่อและคำอธิบายของ Users อยู่ที่ `pages.roleUsers`
- ข้อความเรื่องสิทธิ์ฝั่งหน้าจอ **ไม่แสดงในหน้านี้** (อยู่ในคู่มือส่วน `สำหรับการทดสอบ` ที่เดียว)

## ช่องสิทธิ์ (ทั้ง 2 หน้า + Drawer ผู้ใช้)

- `components.permissionCell(level, scope, kind)` + `components.permissionLegend()` (ดู `ui-standards.md`) · ไม่มีพื้นสี ไม่มี Emoji / สัญลักษณ์ ✓ ✕ – ◌
  - แก้ไข = `แก้ไข` ตัวหนาสีหลัก (+ `เฉพาะทีม` ตัวเล็กสีจาง) · ดู = `ดู` สีจาง · ไม่เห็น = ช่องว่าง · ปุ่มเฉพาะ อนุญาต = `อนุญาต` ตัวหนา · ไม่อนุญาต = ว่าง
- โครงตาราง: หัวตารางติดบน · คอลัมน์ชื่อติดซ้าย · แถว ~40px · เส้นแบ่งแถวจาง ไม่มีเส้นแบ่งคอลัมน์ · Hover = พื้นจางทั้งแถว (Permissions: ทั้งคอลัมน์ด้วย)
- หัวกลุ่ม Module พับได้ (ตัวพิมพ์ใหญ่สีจางแบบเมนูข้าง) · สิทธิ์ย่อยย่อหน้าตัวเล็กสีจาง (ไม่มี `└`) · กลุ่มสุดท้าย `ทั้งระบบ` (ส่งออก)

## หัวหน้า

- ชื่อหน้าภาษาอังกฤษ + `?` · คำอธิบาย 1 บรรทัด (Permissions `สิทธิ์ของแต่ละบทบาทในแต่ละหน้า` · Users `บทบาทของผู้ใช้และสิทธิ์ที่มีผลจริง`)
- ปุ่ม: `ประวัติการแก้ไข ▾` (Audit ของหน้า: สิทธิ์ + บทบาท / ผู้ใช้) · `ส่งออก ▾` · แก้ไข / บันทึก / ยกเลิก
  - Permissions โหมดแก้ไข: `⋯` = `คืนค่าตั้งต้นทั้งหมด` (กล่องยืนยัน) · Users โหมดแก้ไข: `+ เพิ่มผู้ใช้`
- ส่งออก: Permissions = เมทริกซ์ `Roles-Permissions_{YYYYMMDD}` · Users = ผู้ใช้ที่กรอง × สิทธิ์ที่มีผลจริงของ Module ที่เลือก

## Permissions

- แถบเครื่องมือ: `Module` (ทุก Module / Module เดียว / ทั้งระบบ) · `บทบาท` (หลายค่า) · คีย์ลัด (โหมดแก้ไข) · Legend (ขวา) — ไม่มี Checkbox `เฉพาะที่ต่างจากค่าตั้งต้น`
- แถว = หน้า จัดกลุ่มตามเมนูข้าง (มีเลขขั้นของ Sales Planning) · ไม่มีแถวเกี่ยวกับคู่มือ (เห็นเสมอ)
- หัวคอลัมน์บทบาท (ตามลำดับบทบาท): ชื่อ + Chip `สร้างเอง` (บทบาทที่ไม่ใช่ตั้งต้น) + `⋯` / บรรทัด 2 `{n} คน` = ลิงก์หน้า Users ที่กรองบทบาทนั้น
  (ส่งผ่าน `ui.usersRoleFilter` อ่านครั้งเดียว · สถานะ = ทั้งหมด) — ไม่มี `เห็น x หน้า · แก้ไข y หน้า`
- เมนู `⋯` ของบทบาท (แทนหน้า Roles เดิม · หัวข้อกลุ่มในเมนู):

  | กลุ่ม | รายการ | โหมด |
  |---|---|---|
  | ข้อมูลบทบาท | แก้ชื่อและคำอธิบาย… · ตั้งหน้าเริ่มต้น… · เลื่อนไปซ้าย · เลื่อนไปขวา | แก้ไข |
  | สิทธิ์ | ตั้งทั้งคอลัมน์เป็น… · คัดลอกสิทธิ์จากบทบาท… · คืนค่าตั้งต้นของบทบาทนี้ | แก้ไข |
  | อื่นๆ | ดูตัวอย่างในมุมมองนี้ (ผู้ใช้คนแรกของบทบาท → หน้าเริ่มต้นของบทบาท) · ดูรายชื่อผู้ใช้ | ทุกโหมด |
  | อันตราย | ลบบทบาท (เฉพาะบทบาทที่สร้างเอง · มีผู้ใช้ = กล่องแจ้งว่าลบไม่ได้) | แก้ไข |

- แผงด้านข้าง (เพิ่มบทบาท · แก้ชื่อ · ตั้งหน้าเริ่มต้น ใช้ฟอร์มเดียว): ชื่อ (ห้ามว่าง ห้ามซ้ำ) · คำอธิบาย · คัดลอกสิทธิ์จาก (เฉพาะเพิ่ม · ไม่คัดลอก = ดูทุกหน้า) ·
  หน้าเริ่มต้น (Dropdown จากหน้าที่บทบาทเห็นตามสิทธิ์ที่จะได้ · ว่าง = `อัตโนมัติ ({หน้า})`)
- โหมดแก้ไข: คอลัมน์สุดท้าย `+ เพิ่มบทบาท`
  - คลิกช่อง = Popover ชิดช่อง `ไม่เห็น | ดู | แก้ไข` (+ `ทุก Channel | เฉพาะทีม` เมื่อกำหนดขอบเขตได้) · ปุ่มเฉพาะ `ไม่อนุญาต | อนุญาต` · กดแล้วปิดทันที
  - คีย์บอร์ด: ลูกศรเลื่อนช่อง · `1` ไม่เห็น · `2` ดู · `3` แก้ไข · `T` สลับเฉพาะทีม · Enter เปิดตัวเลือก (โฟกัสอยู่ช่องเดิมหลังเปลี่ยน)
  - คลิกชื่อหน้า = `ตั้งทั้งแถวเป็น…` (เฉพาะบทบาทที่แสดง)
  - ช่องที่แก้ในรอบนี้ = ขอบล่างสีหลักบาง (ไม่มีจุดที่มุมช่อง)
  - หลังทุกการแก้ใช้กฎสิทธิ์ย่อยและแจ้ง `ปรับสิทธิ์ย่อยให้ไม่สูงกว่าหน้าหลัก: …`

## Users

- แถบเครื่องมือ: ค้นหาชื่อ · `Module` (ตัวเลือกเดี่ยว ไม่มีทุก Module · + ทั้งระบบ · ค่าเริ่มต้น Sales Planning · จำที่ `ui.usersModule`) · บทบาท (หลายค่า) ·
  Channel ของทีม (+ ไม่มีทีม) · สถานะ (ค่าเริ่มต้น `ใช้งาน`) · Legend
- ตาราง: ชื่อ · บทบาท · บุคลากร (CR-32) · ทีม (ติดซ้าย 170 / 170 / 140 / 140px) + คอลัมน์สิทธิ์ = หน้าของ Module (หน้าที่มีสิทธิ์ย่อย = หัวคอลัมน์ 2 ชั้น `หน้า` + สิทธิ์ย่อย)
  - CR-32 บุคลากร = ชื่อจาก `person.userId` (หรือ `–`) · แหล่งเดียวของการผูก (1:1 · บุคคลเท่านั้น) · ทีมและสิทธิ์เฉพาะทีมอ่านผ่านบุคลากรนี้
  - ช่องสิทธิ์ **อ่านอย่างเดียว** = สิทธิ์ที่มีผลจริงหลังรวมทุกบทบาท (`permissions.effectiveRows`) · Tooltip `ได้จากบทบาท: {บทบาท}`
  - จัดกลุ่มตามบทบาทแรก (ลำดับบทบาท) หัวกลุ่มพับได้ `{บทบาท} · {n} คน` · บทบาทอื่นเป็น Chip ในคอลัมน์บทบาท · ไม่มีบทบาท = กลุ่ม `ยังไม่มีบทบาท`
  - ทีม `{Channel} · Manager/Officer` ณ เดือนปัจจุบันจำลอง (หลายค่าได้) = ลิงก์หน้า Sales Person Management `#person-{id}` · ไม่มีทีม = ว่าง
  - ผู้ใช้ที่ปิดใช้งาน = แถวจาง ช่องสิทธิ์ว่าง (Tooltip `ผู้ใช้ปิดใช้งาน · ไม่มีสิทธิ์`) · ไม่มีคอลัมน์สถานะ · ชื่อไม่มีเส้นใต้ (Hover = ลิงก์)
  - 1920×1080 ไม่เลื่อนแนวนอนทุก Module
- โหมดแก้ไข:
  - คลิกคอลัมน์บทบาท = Popover Checkbox บทบาท (หลายค่า · เรียงตามลำดับบทบาท) · ช่องสิทธิ์ในแถวเปลี่ยนทันที · แถวที่แก้มีแถบซ้าย
  - `⋯` หลังชื่อ = ปิด / เปิดใช้งาน (หรือใน Drawer)
  - CR-32 คอลัมน์บุคลากร = ตัวเลือกบุคลากรประเภทบุคคลที่ยังไม่ผูก (+ คนเดิม · `–` = ยกเลิกการผูก · `permissions.linkUser`) · บันทึกลง `master.salespeople` + Audit `person.userId`
  - `+ เพิ่มผู้ใช้` (กล่อง): ชื่อ · เชื่อมกับบุคลากร (ไม่บังคับ · ที่ทำงานอยู่และยังไม่ผูก · เลือกแล้วเติมชื่อ · ผูกผ่าน `person.userId`) · บทบาท (อย่างน้อย 1)
  - บัญชีผู้ใช้สร้างจากหน้า Sales Person Management ได้ด้วย (รายชื่อผู้ใช้ชุดเดียวกัน `master.users`)
- คลิกชื่อ = Drawer แท็บ `ข้อมูล` (ชื่อ · บทบาท · บุคลากร · ทีม · หน้าเริ่มต้นที่มีผล · สถานะ) · `สิทธิ์ที่มีผลจริง` (ทุก Module + บทบาทต้นทาง) · `ประวัติ`

## บันทึก (ทั้ง 2 หน้า)

1. ต้องมีผู้ใช้ที่เปิดใช้งานและแก้ Role Management ได้อย่างน้อย 1 คน ไม่อย่างนั้นขึ้น `บันทึกไม่ได้`
2. กล่องสรุป `เปลี่ยน {n} ช่อง ใน {m} บทบาท · กระทบผู้ใช้ {k} คน` (+ แก้ข้อมูลบทบาท n รายการ รวมหน้าเริ่มต้นและลำดับ · + แก้ผู้ใช้ n คน)
3. ถ้าเอาสิทธิ์แก้หน้านี้ออกจากตัวเอง ต้องยืนยันอีกครั้ง (danger)
4. บันทึก `master.roles` · `master.permissions` · `master.users` + Audit log แล้วโหลดหน้าใหม่
   (เมนู ตัวเลือกมุมมองผู้ใช้ และปุ่มทุกหน้าเปลี่ยนตามสิทธิ์ใหม่)
