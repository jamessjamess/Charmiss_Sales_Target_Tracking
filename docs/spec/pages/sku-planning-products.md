# SKU Planning · สินค้าในแผน (`modules/sku-planning`)

ส่วนหนึ่งของ [sku-planning.md](sku-planning.md) (แยกไฟล์ CR-37 เพราะใกล้ 30 KB) · เพิ่มสินค้าในแผน · Status สินค้าในแผน · ช่วง Listing · แถว Bundle

## เพิ่มสินค้าในแผน (CR-34 แทน `+ เพิ่ม SKU` · `+ เพิ่มสินค้าใหม่` · `+ สร้าง NPD`)

- ปุ่มเดียว `+ เพิ่มสินค้าในแผน` (โหมดแก้ไข) ที่แถบแก้ไข และแถวคงเหลือเมื่อทั้งปีขาด → Drawer `เพิ่มสินค้าในแผน · {หน่วยขาย}` 3 แท็บ (`core/plan-edits.js` ตรวจสิทธิ์ในฟังก์ชัน):

| แท็บ | รายการ | เมื่อเพิ่ม |
|---|---|---|
| สินค้าเดิมที่ยังไม่เคยขายในหน่วยขายนี้ | `planEdits.candidates().existing`: สินค้าที่ขายอยู่ (สินค้าเดิม / Listing ใหม่) ที่ยังไม่อยู่ในแผน · ค้นหา · Series · Category · L12M ชิ้นรวมทุกหน่วยขาย · เรียง L12M มากไปน้อย · ขาดข้อมูลจำเป็นเลือกไม่ได้ (ท้ายรายการ) | แถว 0 ทุกเดือน ตั้งแต่เดือนที่เลือก (ค่าเริ่มต้น ม.ค.) · ยังไม่ได้ Listing = Listing ใหม่ `source: 'skuPlanning'` ตอนบันทึก |
| NPD ที่ยืนยันแล้ว | `candidates().npd`: ประเภท NPD ยืนยันแล้ว (ไม่รวมคำขอ) + เดือนเปิดตัว | เดือนเริ่ม = `ตามเดือนเปิดตัวของแต่ละรายการ` (หรือเดือนที่เลือก ไม่ก่อนเปิดตัว) |
| ขอ NPD เพิ่ม | ฟอร์มเดิมของ + สร้าง NPD + `เหตุผล / แนวคิดสินค้า` · ปุ่ม `ส่งคำขอ NPD` · ต้องมีสิทธิ์ย่อย สร้าง NPD (ไม่มี = แท็บปิด + เหตุผล) | `planEdits.requestNpd` → `calc.createSalesNpd` บันทึกลง Master ทันที (สินค้า `SALES_REQUEST` · แผน NPD ที่มา `SALES` + `requestedBy` · `reason`) + แถว `ขอ NPD` |

- เลือกหลายรายการในแท็บ 1 / 2 = เดือนเริ่มเดียวกัน แก้รายแถวได้ที่คอลัมน์ช่วงเวลาขาย · `addToPlan` ปฏิเสธผู้ไม่มีสิทธิ์ (`permission`) และรายการนอกแท็บ (`invalid`)
- ข้อความแจ้ง `มีสินค้าใหม่ที่ Listing แล้วแต่ยังไม่อยู่ในแผน n รายการ` (NPD ยืนยันแล้วที่ยังไม่อยู่ในแผน) + ลิงก์ `เพิ่มสินค้าในแผน` เปิดแท็บ NPD ที่ยืนยันแล้ว (โหมดแก้ไข)
- `เพิ่มทั้ง Series` (เมื่อเลือก Series) คงเดิม (`calc.addableSkus`)
- CR-30 Listing สถานะ `เสนอขาย` = Listing แล้ว (ไม่อยู่ในแผนตั้งต้น) · เพิ่มแล้วมีป้าย `ยังไม่ยืนยัน Listing`

## Status สินค้าในแผน (CR-35)

- รหัสที่แสดง (คอลัมน์ชื่อ · Tooltip · ส่งออก · กล่องเพิ่มสินค้า · ข้อมูลที่ต้องตรวจ) = `calc.productCode` · คำขอ = `NPD-YYMM-NNN` + ป้าย `ชื่อชั่วคราว`
- `Delete` ตั้งแต่เดือน `deletedFrom`: แถวอ่านอย่างเดียวตั้งแต่เดือนนั้น (ค่าเดิมคงไว้ · `state.reason 'deleted'`) + ป้าย Delete · ข้อมูลที่ต้องตรวจกลุ่ม `delete` · ไม่อยู่ในกล่องเพิ่มสินค้า
- `Discontinued`: แก้ได้เฉพาะหน่วยขายที่เคยขาย (`soldInUnit` → `cellSource` / `lockReason` opts `soldHere`) · ไม่อยู่ในแผนตั้งต้น · เพิ่มจากกล่องได้เฉพาะหน่วยที่เคยขาย (`calc.addableSkus` + history)
- การล็อกช่องยังใช้ Status จากวันที่ (`calc.dateStatusAt`) · Status ที่แสดงใช้ `calc.productStatus` (Delete → Request → วันที่)
- CR-36 เดือนในช่วง Clearance = อ่านอย่างเดียว `–` + Tooltip `วางแผนที่ Price & Promotion › Clearance` (`state.reason clearance` · แทนการแบ่ง Stock อัตโนมัติของ CR-30) ·
  ค่าเดิม (Override) คงไว้ + ข้อมูลที่ต้องตรวจ `มีแผนสินค้า Clearance` (`calc.clearanceLockedRows`) + ปุ่ม `ล้างค่า` ในโหมดแก้ไข (`calc.clearClearanceCells`) · แผน Clearance ไม่นับในแผนนี้
- CR-36 ข้อความ `มีสินค้าใหม่ที่ Listing แล้วแต่ยังไม่อยู่ในแผน n รายการ` นับด้วย `calc.listedNotPlanned` · รับ `ui.skuAddHandoff` จาก Launch & Listing (เปิด เพิ่มสินค้าในแผน แท็บ NPD ที่ยืนยันแล้ว)

## ช่วง Listing (CR-30)

- แผนตั้งต้นใช้ Listing ที่มีช่วงทับปีแผนและไม่ใช่เสนอขาย (`calc.listedInYear`)
- เดือนนอกช่วง Listing ของหน่วยขายนี้ = ล็อก 0 (`calc.listingOutside`): ก่อน `fromMonth` = `ก่อนเดือนเริ่มวางขายใน Listing` · หลัง `toMonth` ของสินค้าที่ถอด = `ถอดจาก Listing แล้ว`
- NPD แบบไตรมาสใช้ต้นไตรมาสเป็นเดือนเปิดตัวชั่วคราว → เดือนก่อนหน้าล็อกเป็น Planned (22110 `2028-Q2` = ล็อก ม.ค.–มี.ค. 2028)

## แถว Bundle (CR-37)

- Bundle (`product.kind = 'bundle'`) เป็นแถวของตัวเองเหมือน SKU ทั่วไป · จำนวนเป็น `ชุด` · Net Sales คิดจากราคา Bundle ตามลำดับราคาเดิม (ไม่แตกยอดไปที่ชิ้นส่วน)
- คอลัมน์ชื่อ: ป้าย `Bundle` (`components.bundleTag` · Tooltip ส่วนประกอบ) ต่อท้ายชื่อ · บรรทัดที่ 2 = `รหัส · 12130 × 1 + 12140 × 1 · ชุด` (ส่วนประกอบตัดด้วย … · Tooltip เต็ม · ค้นหาด้วยรหัสชิ้นส่วนได้)
- ชิ้นส่วนที่เป็น Delete ภายในปีแผน (`calc.bundleDeletedParts`) = แถวขอบเหลือง (`tr.is-bundle-check`) + ป้าย `ชิ้นส่วนต้องตรวจ` + Tooltip `ชิ้นส่วน <รหัส> สถานะ Delete` · ไม่ล็อกแถว
- แถวรวมแผน (ชิ้น) นับ 1 ชุด = 1 (ตรงกับยอดขาย) · Tooltip หัวแถว `รวม Bundle N ชุด (เท่ากับ M ชิ้นส่วน)` (อัปเดตทุกครั้งที่แก้ค่า)
- ประเภทสินค้าในแผน = `calc.planTypeOf` ตาม Status / Listing ของ Bundle เอง (CR-34 / CR-35)
- `+ เพิ่มสินค้าในแผน` แท็บ 1 และ 2 มี Bundle (ป้าย `Bundle`) + ตัวกรอง `ประเภทสินค้า` (สินค้าเดี่ยว / Bundle · `addState.kind`)
- Flag `bundle` ปิด (`calc.bundleVisible`): `skuPlanGrid` ไม่มีแถว Bundle และยอดรวมไม่นับ · `availableSkus` / `addableSkus` ไม่มี Bundle · ค่าในแผนยังอยู่ใน Store
