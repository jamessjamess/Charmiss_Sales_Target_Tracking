# มาตรฐาน UI · คำศัพท์ · สี · Component · กราฟ

## ภาษาและคำศัพท์

- ภาษาไทยทางการ ประโยคสั้น ไม่ใช้ภาษาพูด · คำอธิบายใต้หัวข้อ 1 บรรทัด บอกว่าหน้านี้ทำอะไร (วิธีใช้อยู่ใน Tooltip หรือแผง ?)
- ศัพท์ธุรกิจใช้ภาษาอังกฤษ: Target · Net Sales · Sale Amount · GP · SKU · Channel · Account · Series · NPD · Forecast · Baseline
- ชื่อขั้นตอน (CR-23) เป็นภาษาอังกฤษทั้ง 4 ขั้น (ชื่อเต็ม = ชื่อในเมนู) · Tooltip ชื่อหน้า คำอธิบายใต้หัวข้อ และข้อความในหน้าเป็นภาษาไทย ·
  ชื่อหน้าใน Product Master / Account Master เป็นภาษาไทย · ข้อความที่อ้างถึงหน้า (เช่น `ไปที่หน้า {page}`) อ่านชื่อจาก content.js

  | ขั้น | ชื่อหน้า | Tooltip | ทำอะไร |
  |---|---|---|---|
  | 1 | Annual Target | กำหนดเป้าหมายประจำปี | Total Target และเป้าหมายของแต่ละ Channel |
  | 2 | Sub-channel Allocation | จัดสรรเป้าหมายหน่วยขาย | แบ่งเป้าของ Channel ลงหน่วยขาย และกระจายเป็นรายเดือน |
  | 3 | SKU Planning | วางแผนยอดขายราย SKU | แผนจำนวนชิ้นราย SKU |

## ตัวเลข

- ตารางที่กรอก = บาทเต็ม ไม่มีทศนิยม · กราฟและรายงาน = ล้านบาท 2 ตำแหน่ง หน่วยอยู่ที่หัวคอลัมน์หรือแกน
- % ในช่องกรอก 2 ตำแหน่ง · การเติบโต 1 ตำแหน่ง (เป้าหมาย 0 → `–` · ไม่มียอดปีก่อน → `ใหม่`)
- ห้ามตัวย่อ "ล." · ห้ามตัดตัวเลขด้วย "…" (คอลัมน์ไม่พอให้ลดขนาดตัวอักษร) · ห้ามปนหน่วยในบรรทัดเดียว · ตัวเลขใช้ tabular-nums ชิดขวา
- ห้ามแสดงตัวเลขเดียวกันซ้ำในหน้าเดียวโดยไม่มีเหตุผล · ห้ามเขียนตัวเลขผลลัพธ์ลงใน HTML หรือข้อความ

## สี (Token ใน `styles/tokens.css`)

| ความหมาย | ค่า |
|---|---|
| คงเหลือ `--status-complete / short / over / empty` | จัดสรรครบ (±1 บาท) เขียว · **ขาด แดง** · **เกิน เหลือง** · ยังไม่กำหนด เทาอ่อน |
| ที่มาของช่อง | ล็อก เทา · กรอกเอง ฟ้า · ระบบเติม เขียว · Clearance ส้ม |
| Workflow **[Phase 2]** | ฉบับร่าง เทา · รออนุมัติ ฟ้า · อนุมัติ เขียว · ส่งกลับแก้ไข แดง · ต้องตรวจสอบใหม่ เหลือง |
| สิทธิ์ | CR-31 ตารางสิทธิ์ไม่ใช้พื้นสี: `แก้ไข` / `อนุญาต` ตัวหนาสีหลัก · `ดู` สีจาง · ไม่เห็น = ว่าง (`permissionCell`) |
| อื่นๆ | Channel `--ch-*` · คน `--person-*` · Series `--ser-*` · Status สินค้า `--c-st-*` · ขั้น NPD `--npd-*` · Promotion `--promo-*` · Waterfall `--wfc-*` · กราฟ `--chart-*` |
| ประเภทสินค้าในแผน (CR-34) | `--c-type-*` สินค้าเดิม = สีหลัก · NPD ยืนยันแล้ว ม่วงเข้ม · ขอ NPD ม่วงอ่อนลายเส้น + ขอบประ · Clearance เทา · ป้ายและสีอยู่ที่ `labels.planTypes` ที่เดียว |

- class คงเหลือ: `alert-<status>` (พื้น) · `text-<status>` · `rem-<status>` (แถวคงเหลือ) · `dot-<status>` / ป้ายทั่วไป `tag-ok | tag-warn | tag-danger | tag-muted`
- **ห้ามสื่อสถานะด้วยสีอย่างเดียว** ต้องมีข้อความกำกับเสมอ

## โครงหน้า

- Header: ชื่อระบบ + ป้าย `Prototype` · มุมมองผู้ใช้ (ข้อความ `(จำลองสำหรับการนำเสนอ)` อยู่ใน Tooltip ของป้าย · Dropdown กว้างสุด 24em ให้ชื่อแสดงครบ · จอ ≤ 1280px 21em · มือถือเต็มแถว) · เกี่ยวกับ Prototype · รีเซ็ตข้อมูล
- แถวหัวข้อ: `ชื่อหน้า [ปีแผน ▾] …… [ส่งออก ▾] [แก้ไข]` + คำอธิบาย 1 บรรทัด · CR-27 ไม่มี `ขั้นที่ x/4` ในหัวข้อ — เลขขั้นอยู่ที่เมนูข้าง (รวมตอนพับเมนู) และปุ่มก่อนหน้า/ถัดไป ·
  CR-25: เลขขั้นคงที่ทุกบทบาท (x = ลำดับขั้นจริง แม้ขั้นก่อนหน้าถูกซ่อน)
  - CR-28: ปุ่ม `?` ต่อท้ายชื่อหน้า (`components.pageHelp`) ทุกหน้าในเมนูยกเว้นคู่มือ: หน้านี้ใช้ทำอะไร · ผู้แก้ไข (จากสิทธิ์จริง) · ขั้นตอนหลัก ≤ 3 · ดูคู่มือทั้งหมด ·
    หัวข้อเพิ่มของหน้า (`ctx.addHelp`) — ปุ่ม `?` อื่นในหน้า (เช่น แถวเครื่องมือ SKU Planning) ไม่ใช้แล้ว
  - ชื่อหน้ามี Tooltip · หัวข้อไม่ใส่ปี · ตัวเลือกปีขนาดเท่าหัวข้อ
  - เปลี่ยนปีเมื่อมีรายการที่ยังไม่บันทึก ต้องยืนยันก่อน
  - **[Phase 2]** มีป้ายสถานะ + `ประวัติ ▾` + ปุ่มส่งอนุมัติ
- Side Menu 5 กลุ่ม (Sales Planning · Product Master · Account Master · Role Management · ข้อมูลโครงการ) แสดงเฉพาะหน้าที่ผู้ใช้เห็น
  - CR-25: กลุ่มที่ไม่เหลือหน้าให้เห็นไม่มีหัวกลุ่ม · คู่มือการใช้งาน (กลุ่ม `ช่วยเหลือ` · CR-28) เห็นทุกบทบาท · ไอคอนขั้นเป็นเลขขั้นจริง (Sales Officer เห็น 2 · 3 · 4)
  - Role Management = Permissions (K) · Roles (R) · Users (U) · ไอคอนตัวอักษรห้ามซ้ำกับหน้าอื่น
  - กว้าง 236px พับเหลือ 56px (พับแล้วแสดงไอคอน + Tooltip) · จอ < 1024px เลื่อนออกด้วย ☰
  - CR-24: เปิดเป็นค่าเริ่มต้นทุกหน้า ไม่พับเองในหน้าใด (เลิกกฎ SKU Planning ของ CR-11) · ผู้ใช้พับเองได้ จำที่ `ui.sidebarCollapsed`
  - ชื่อบรรทัดเดียว ยาวเกินใช้ชื่อย่อ
  - ขั้นที่ 4 แสดงจำนวนรายการที่ต้องดำเนินการ
- ปุ่มก่อนหน้า/ถัดไปใช้ชื่อในเมนู (`ถัดไป: Sub-channel Allocation →`) และมีเฉพาะ 4 ขั้นของ Sales Planning
  - CR-25: ข้ามขั้นที่มองไม่เห็น (ไม่มีขั้นก่อนหน้าที่เห็น = ไม่มีปุ่มก่อนหน้า) · ขั้นสุดท้าย `กลับขั้นแรก ↺` ไปขั้นแรกที่เห็น (ไม่แสดงถ้าเป็นหน้านี้)
- **Toast** (CR-25 · `layout.showToast` สไตล์ `.toast` ใน components.css): ข้อความสั้นล่างกลางจอ แสดงครั้งเดียวหลังโหลดหน้า หายเองใน ~4.5 วินาที
  ใช้เมื่อสลับมุมมองผู้ใช้แล้วหน้าปัจจุบันถูกซ่อน: `สลับเป็น {บทบาท} · ไปที่ {หน้า}`
- **ยอดขายย้อนหลัง** (CR-23 · CR-24) ในตารางเป้าหมาย: `2024 · 2025 · L12M ⓘ` ใต้หัวกลุ่ม `ยอดขาย (ล้านบาท)`
  (ปีจาก `clock.fullYears()` ห้าม Hardcode · หัว L12M มีบรรทัดเล็ก `ก.ย. 25 – ส.ค. 26` · Tooltip ปี 2025 บอกช่วงที่อยู่ใน L12M ด้วย)
  · การเติบโตและแท่งเทียบกับ L12M
- **ยอดขายอ้างอิงรายเดือน** (CR-24): หัวเดือนมีบรรทัดเล็กบอกปีที่ใช้ (`26` / `25` สีเตือน) + เส้นแบ่งจางก่อนเดือนแรกที่ใช้ปีก่อนหน้า
- แถบบริบทแถวเดียว (SKU Planning): `Channel | {unitLabel} ‹ ▾ › | ผู้รับผิดชอบ · {gpLabel} · เป้าหมายทั้งปี · ยอดขาย L12M ⓘ · การเติบโต`
  (Sub-channel Allocation: ปุ่ม Channel + ตัวเลขของ Channel · เลือกหน่วยขายจากตาราง)
  - Dropdown ตอนปิดแสดงชื่ออย่างเดียว ตอนเปิดแสดงชื่อ · ผู้รับผิดชอบ · คงเหลือ (ข้อความ + สี)
  - แถบผู้รับผิดชอบรายเดือนแสดงเฉพาะเมื่อมีหลายคนในปี
  - จอ < 1800px ย่อตัวอักษร · จอ < 1600px ขึ้นบรรทัดใหม่ได้
- **แถวคงเหลือ** ในตาราง (ห้าม Chip คงเหลือในตาราง): ป้ายซ้าย `คงเหลือ · ขาด / เกิน / จัดสรรครบ / ยังไม่กำหนด`
  ตัวเลขอยู่ในคอลัมน์เดียวกับตัวเลขที่ต้องปรับ พื้นแถวสีอ่อนตามสถานะ · Chip คงเหลือใช้เฉพาะใน Dropdown หรือเมนู

## โหมดดู / แก้ไข

- ทุกหน้าที่มีตัวเลขเปิดเป็นโหมดดู: ตัวเลขเป็นข้อความ ไม่มีช่องกรอก ไม่มีปุ่มเพิ่ม/ลบ
- กดแก้ไข → Module แก้สำเนา (draft) ไม่เขียน store จนกด บันทึก · ยกเลิก = ทิ้ง draft
- CR-33 ข้อยกเว้น: Account Master แก้ไขรายรายการ (Drawer / Dialog บันทึกทันที + Toast · ไม่มีปุ่มแก้ไขที่หัวหน้า · ดู `pages/sales-units.md`)
  - CR-35 หน้าที่ไม่มี workflowBar แสดง `ดูอย่างเดียว · แก้ไขได้โดย {บทบาท}` เอง (`components.viewOnlyNote(ids)` · ชื่อบทบาทจาก `permissions.editors`)
- CR-35 สัญญาณโหมดแก้ไข: โหมดดูไม่มี Hover บนช่อง / แถวที่แก้ไม่ได้ · โหมดแก้ไข = Hover + เคอร์เซอร์ชี้ + ข้อความวิธีแก้ต่อท้ายแถบโหมดแก้ไข (`editBanner` opts `suffix` · `labels.workflow.editingHint`)
- แถบ `โหมดแก้ไข · มีรายการที่ยังไม่บันทึก n รายการ` · ช่องที่ยังไม่บันทึกมีขอบหนา · การลบรายการนับเป็นรายการที่ยังไม่บันทึก
- เตือนเมื่อออกจากหน้า (beforeunload) และยืนยันก่อนเปลี่ยนหน่วยขาย · Series · โหมด · เดือน
- ปุ่มลบ = ไอคอนถังขยะ + กล่องยืนยันแบบ danger · ปุ่มเพิ่มมีข้อความ `+ เพิ่ม …`
- ปุ่ม แก้ไข / บันทึก / ยกเลิก มาจาก `workflowBar` ตามสิทธิ์ของหน้า (ห้ามเขียน Logic ใน Module)
  - ไม่มีสิทธิ์ = `อ่านอย่างเดียว · หน้านี้แก้ไขโดย {บทบาท}` + ปุ่ม `สลับเป็น {บทบาท}`
  - Sales ที่ดูหน่วยขายนอกทีม = `อ่านอย่างเดียว · หน่วยขายนี้อยู่ในทีม {Channel}`
- ยอมรับ / ส่ง / ลบ ใช้กล่องยืนยัน `<dialog>` ที่สรุปตัวเลขหลัก ส่วนการส่งกลับแก้ไขต้องมีเหตุผล **[Phase 2]**

## ส่งออกไฟล์

- `ส่งออก ▾` มี Excel และ CSV
  - Excel มีหัวไฟล์ (ปีแผน · วันเวลาที่ส่งออก · มุมมองผู้ใช้ · สถานะ **[Phase 2]**)
  - ตัวเลขเป็นชนิดตัวเลขจริง (% = ทศนิยม รูปแบบ 0.00% · เงิน #,##0) · ตรึงแถวหัวตาราง · ห้าม Merge cell
  - CSV ไม่มีหัวไฟล์ มี BOM
- ชื่อไฟล์ `{หน้า}_{ปี}_{หน่วยขาย}_{YYYYMMDD}` (Phase 2 มีสถานะต่อท้าย) · มีรายการที่ยังไม่บันทึก = ถามว่าส่งออกค่าใด
- ไม่มีสิทธิ์ส่งออก = ไม่แสดงปุ่มส่งออก / CSV / พิมพ์
