## 1. นาฬิกากลาง (`core/clock.js` · `SP.core.clock`)

- **ทุกจุดที่ต้องรู้เดือนปัจจุบันอ่านจากนาฬิกากลางเท่านั้น** ห้าม `new Date()` (ยกเว้นเวลาของวันใน `clock.now()`) และห้ามเขียนเดือน / ปีตายตัว · CR ระบุชื่อ `SP.clock` แต่ใช้ `SP.core.clock` เดิมตามกติกา namespace ของ CLAUDE.md
- สถานการณ์ที่เลือก = `app.scenario` ใน sessionStorage (`SP:app.scenario`) · นาฬิกาอ่านเองตอนโหลดเพราะโหลดก่อน `core/store.js` · `refresh()` หลังรีเซ็ต
- ฟังก์ชัน: `scenarioId` · `currentMonth` · `lastClosedMonth` · `asOfDate` / `asOfLabel` · `planYear` · `now` · `l12mRange` · `referenceYear` · `isClosed` · `fullYears` · `label` · `rangeLabel` · `horizonEnd` ·
  `withScenario(id, fn)` / `withMonth(month, fn)` (เปลี่ยนชั่วคราวแล้วคืนค่าเสมอ) · `at(month)` (นาฬิกาที่หยุดไว้ที่เดือนหนึ่ง)
- **เวลาที่ประทับ** (`clock.now()`) = วันที่ของสถานการณ์ + เวลาจริงของเครื่อง (`YYYY-MM-DDTHH:MM:SS`) — ส่งขออนุมัติ · อนุมัติ · ความคิดเห็น · เปิดรอบ · บันทึกทุกหน้า · หัวไฟล์ส่งออก · วันที่ในชื่อไฟล์ (ผู้ใช้เลือก)
- **ผู้รับผิดชอบ · ทีมขาย · สิทธิ์ขอบเขตทีม · Role Management · รายงาน** ใช้เดือนปัจจุบันของนาฬิกา (`store.currentKey()` = `clock.currentMonth()` · เดิม มี.ค. ของปีแผน · ผู้ใช้เลือก) ·
  `ui.currentMonth` (DEMO_FORECAST_MONTH) เหลือเฉพาะโหมดปรับแผน **[Phase 2]**
- ค่าคงที่ `DEMO_CURRENT_MONTH` ถูกตัด · `PLAN_HORIZON_END` คงที่ `2027-12`

## 2. ยอดอ้างอิงรายเดือนแบบทั่วไป

- ยอดอ้างอิงของเดือน M ในปีแผน = ยอดจริงของเดือนเดียวกันในปีล่าสุดที่เดือนนั้นปิดแล้ว (≤ เดือนปิดล่าสุด) → ผลรวม 12 เดือน = L12M เสมอ
- `calc.actualMonthValue` ใช้เฉพาะเดือนที่ปิดแล้ว (`clock.isClosed`) และไม่เกิน `actualMonths` ของปี (ข้อมูลที่มี)
- S1 ได้ค่าเดิมทุกค่า (Test cr41-4: 21 หน่วยขาย + ทุก SKU × หน่วยขาย เทียบกับกติกาเดิม ม.ค.–ส.ค. 2026 · ก.ย.–ธ.ค. 2025)
- S2: ม.ค. = ปี 2027 (ยอดตัวอย่าง) · ก.พ.–ส.ค. = 2026 · ก.ย.–ธ.ค. = 2026 (ยอดตัวอย่าง)
- เดือนของปีแผนที่ยังไม่เกิด (S2 ก.พ.–ธ.ค. 2027) เป็นค่าว่าง (null) ไม่ใช่ 0 → `skuReference` ไม่ใช้เป็นประมาณการ

## 3. ยอดจริงตัวอย่าง (`core/scenario.js` · `buildSample` · ตอนโหลด)

- สร้างตอนโหลดหน้า (หลัง `core/seed.js` ก่อน `core/units.js`) เมื่อสถานการณ์มี `build.sampleFrom` · ฟังก์ชันล้วน สูตรคงที่ ไม่ใช้ `Math.random` → ค่าเดิมทุกครั้งที่โหลด
- ระดับ SKU × หน่วยขาย × เดือน (เหมือนยอดจริงเดิม) + ยอด Net Sales ของหน่วยขาย · ปัดเป็นจำนวนเต็ม · `history.years[ปี].sample = [12 bool]` (isSample)

| เดือน | สูตร |
|---|---|
| ก่อนปีแผน (ก.ย.–ธ.ค. 2026) | ยอดเดือนเดียวกันปีก่อน × (1 + การเติบโตของ Channel) · การเติบโต = เป้าหมาย 2027 เทียบ L12M ใน S1 (MT +1.4% · TT +5.2% · ECOM +10.4% · ผู้ใช้เลือก) · SKU ที่ Status / Listing ไม่ได้ขายเดือนนั้น = 0 |
| ในปีแผน (ม.ค. 2027) | จำนวนในแผน R1 ของเดือนนั้น × ตัวคูณของ Channel (MT 0.95 · TT 1.00 · ECOM 1.12 · `build.planFactor`) · Net Sales ของหน่วย = Net Sales ในแผนของเดือน × ตัวคูณ · หน่วยขายนอกแผน = สูตรก่อนปีแผน |

- แผน R1 คำนวณภายใต้นาฬิกาของ S1 (`build.base`) จึงเท่ากับแผนที่ Lock · `SP.data.actuals` (ยอด 2027 แบบสมมติเดิม) ของเดือนตัวอย่างถูกแทนด้วยยอดตัวอย่าง (ทุกแหล่งของยอดจริงตรงกัน)
- ทุกจุดที่แสดงยอดตัวอย่างมีข้อความกำกับ `ยอดจริงตัวอย่าง (ยังไม่ใช่ยอดจาก TRCLOUD)` ใน Tooltip / หมายเหตุ

## 4. การเลือกสถานการณ์ (`core/layout.js` · `core/scenario.js load`)

- แถบบน: ป้ายสถานการณ์ปัจจุบันถัดจาก `Prototype` (ขอบประสีหลัก) + ปุ่ม `สถานการณ์ Demo ▾` แทน `รีเซ็ตข้อมูล ▾` · ทั้งสองเปิดเมนูเดียวกัน · ทุกบทบาทเลือกได้
- เมนู: 2 สถานการณ์ (จุดเลือก + ชื่อ + คำอธิบาย) · เส้นคั่น · `เริ่มสถานการณ์นี้ใหม่`
- เลือกสถานการณ์อื่น → Dialog `สลับเป็น <ชื่อ> · ข้อมูลที่แก้ไว้ในสถานการณ์ปัจจุบันจะหายทั้งหมด` → ล้าง Session (คงมุมมองผู้ใช้และการพับเมนู) → โหลดสถานการณ์ → หน้าแรกของสถานการณ์ (บทบาทไม่เห็นหน้านั้น = หน้าเริ่มต้นของบทบาท)
- `เริ่มสถานการณ์นี้ใหม่` → Dialog ยืนยัน → โหลดสถานการณ์ปัจจุบันใหม่ → อยู่หน้าเดิม · ปิด Flag `revision` = ปุ่มรีเซ็ตเดิม (เริ่มสถานการณ์ปัจจุบันใหม่)
- `load(S2)`: ภายใต้นาฬิกาของ S1 เขียนค่าตั้งต้นของ 4 ขั้นลง store → ส่งขออนุมัติ (Management 10 ธ.ค. 2026 `เป้าหมายปี 2027 ฉบับแรก`) → ความคิดเห็นของ MD (`อนุมัติ ติดตาม ECOM รายไตรมาส`) →
  อนุมัติและ Lock (MD 15 ธ.ค. 2026) ด้วย `revision.lockFirstRound` (ฟังก์ชันจริงของ CR-38 / CR-39 · Snapshot จริง) · ประวัติ R1 = สร้าง → ส่ง → อนุมัติและ Lock · ตั้งค่าขั้นอนุมัติ = ค่าเริ่มต้น
- เปิดครั้งแรก = S1 · DATA_VERSION เปลี่ยน = ล้างทั้งหมดกลับ S1

## 5. รอบที่ Lock แล้วไม่เปลี่ยนตามนาฬิกา

- Snapshot เก็บเดือนปัจจุบันตอน Lock (`history.asOfMonth`) · `calc.refClock(history)` = นาฬิกาที่หยุดไว้ที่เดือนนั้น → ยอดอ้างอิง · ค่าระบบเติมของแผน SKU · L12M · ปีเต็มของรอบที่ Lock แล้วเท่ากับตอน Lock
- ดู R1 ใน S2 = ตัวเลขเดียวกับ S1 ก่อน Lock (Test cr41-21) · หัวคอลัมน์ / ช่วง L12M ของหน้าวางแผนใช้นาฬิกาของข้อมูลที่แสดง (`calc.refClock`) · ข้อมูล ณ / ยอดจริงใช้นาฬิกาปัจจุบัน

## 6. สิ่งที่แสดงเมื่อเดือนปิดล่าสุดอยู่ในปีแผน (เห็นเฉพาะ S2)

- **Annual Target:** คอลัมน์ `ยอดจริงสะสม (ม.ค. 2027)` (ล้านบาท) + `% ของเป้า <Revision ที่เลือก>` ต่อจาก `เป้าหมาย 2027` (`calc.actualToDate` · ข้อมูลปัจจุบันไม่ขึ้นกับรอบ)
- **Sub-channel Allocation · SKU Planning:** เดือนที่ปิดแล้ว = บรรทัดเล็ก `จริง <ค่า>` ใต้เป้าหมาย / แผน (`components.actualLine` · ต่ำกว่า = แดง · ไม่ต่ำกว่า = เขียว) · SKU Planning: แถวเป้าหมาย (Net Sales / Sale Amount) ทุกมุมมอง · ช่อง SKU เฉพาะมุมมองจำนวนชิ้น (`calc.actualSkuUnits`)
- **Revision Compare:** ตัวเลือก B = `ยอดจริง` ในมุมมองรายเดือน (ระดับ Total / Channel / หน่วยขาย · `revision.actualDataset`) · เดือนที่ยังไม่ปิด = `–` · ยอดรวมนับเฉพาะเดือนที่ปิดแล้ว · มี Revision เดียว = เทียบกับยอดจริงทันที ·
  Channel / Total = ยอดจริงของทุกหน่วยใน Master ของ Channel (รวมหน่วยนอกแผน)
- ไม่มีการคำนวณ Re-forecast อัตโนมัติ **[Phase 2]**

## 7. เดือนที่มีผลของ Revision

- = เดือนถัดจากเดือนปัจจุบันเสมอ (ไม่ก่อนเดือนแรกของปีแผน · `revision.defaultEffective`) · Dialog `เปิด Revision ใหม่` แสดงอ่านอย่างเดียว `มีผลตั้งแต่ มี.ค. 2027 (เดือนถัดไป)` / `(เดือนแรกของปีแผน)` · ตัดการเลือกเองของ CR-38
- S1 หลัง Lock R1 → R2 มีผล ม.ค. 2027 · S2 → R2 มีผล มี.ค. 2027 (ม.ค.–ก.พ. ล็อกจาก R1)
- Clearance (Price & Promotion): เดือนที่ปิดแล้วอ่านอย่างเดียวในโหมดแก้ไข · `กระจายเท่ากันทุกเดือน` ใช้เฉพาะเดือนที่ยังไม่ปิด
- ผู้รับผิดชอบที่สิ้นสุดเดือนปัจจุบัน = `จะสิ้นสุดเดือนนี้` (S2: วิทยา สมใจ สิ้นสุด ก.พ. 2027)
